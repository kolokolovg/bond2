# Design

## Context

См. proposal.md. Сейчас `DatabaseController.shutdown()` закрывает только БД, уже записанную в поле `database`. Операция открытия/миграции выполняется в потоке `bonds2-db` (демон) через `FxBackground`, результат возвращается в поток JavaFX через `Task.onSucceeded`. `requestExit` защищает выход из приложения во время операции, но `Platform.exit()` извне попадает в `MainWindowApp.stop()` минуя эту защиту. Тесты JavaFX (`FxToolkit.start()`) требуют тулкит; локально Monocle есть только потому, что JDK — Liberica Full, а на `temurin` в CI его нет.

## Goals / Non-Goals

**Goals:**
- Не терять БД, открытую после начала завершения, и не снимать блокировку до окончания операции.
- Логику остановки проверять юнит-тестами без JavaFX.
- Запускать UI-тесты и pitest без дисплея в CI.

**Non-Goals:**
- Отмена операции посреди миграции (Flyway не прерывается; полагаемся на транзакции SQLite и резервную копию).
- Изменение поведения `requestExit` внутри приложения.
- Скриншотное тестирование UI.

## Decisions

1. **Флаг остановки в `DatabaseController`.** После `shutdown()` результаты `onResult`/`onCreated`/`onUnexpectedError` игнорируются; полученная `Database` закрывается. Альтернатива (проверять состояние `CLOSED`) отвергнута: оно неотличимо от обычного закрытого состояния.
2. **`Background.run` возвращает `Future<?>` самой работы.** `shutdown()` ждёт его до 30 секунд на потоке JavaFX, не дожидаясь `onDone`: тот приходит через очередь JavaFX, поток которой заблокирован. Результат работы (`Opened`) закрывается напрямую. Таймаут — константа, не настройка. Альтернатива «ждать `onDone`» даёт тупик.
3. **Поток `bonds2-db` — не демон.** Иначе JVM оборвёт операцию, не дожидаясь. Ожидание ограничено таймаутом, зависания процесса не будет.
4. **Порядок остановки в тестируемом методе.** `MainWindowApp.stop()` делегирует методу, принимающему «остановка контроллера» и «снятие блокировки» как действия, чтобы порядок проверялся без JavaFX.
5. **Headless через `-Pheadless=true`.** В `build.gradle.kts` для `test` и `pitest` добавляются `-Dglass.platform=Monocle -Dmonocle.platform=Headless -Dprism.order=sw`. Флаг явный, чтобы локальные прогоны не теряли реальный GTK.
6. **JDK Liberica Full в CI.** `setup-java` с `distribution: liberica`, `java-package: jdk+fx`. Это проверено локально (тесты проходят без дисплея). Альтернатива — `org.testfx:openjfx-monocle:21.0.2`: версия не совпадает с JavaFX 21.0.9, риск несовместимости внутренних классов.

## Risks / Trade-offs

- [Блокировка потока JavaFX до 30 с при выходе] → допустимо: пользователь уже завершил приложение, срок ограничен.
- [Оборванная миграция по таймауту] → транзакции SQLite и резервная копия; восстановление при следующем запуске остаётся ручным.
- [JavaFX берётся из JDK, а не из плагина Gradle] → версии могут расходиться; зафиксировать JDK в CI и проверить прогоном.
- [Monocle не рисует окна и не поддерживает системные диалоги] → тесты проверяют логику контролов, не внешний вид; `FileChooser` в тестах не открывается.
