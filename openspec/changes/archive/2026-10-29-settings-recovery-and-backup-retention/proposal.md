## Why

Сброс испорченных настроек сейчас молчаливый, а после него приложение может незаметно создать новую пустую БД по пути по умолчанию: пользователь с собственным путём решает, что данные пропали. Резервные копии миграций копятся бесконечно, а две миграции в одну секунду конфликтуют по имени копии.

## What Changes

- При сбросе испорченного файла настроек пользователь видит предупреждение с путём к копии `settings.properties.bad-…`.
- После такого сброса автооткрытие не создаёт БД по пути по умолчанию: если файла БД нет, показывается ошибка «файл не найден» с подсказкой про настройки и создание базы. Существующая БД по умолчанию открывается как обычно.
- Имя резервной копии миграции получает числовой суффикс при совпадении метки времени, вместо ошибки.
- После успешной миграции хранятся три последние резервные копии этого файла БД; более старые удаляются. При неудачной миграции копии не удаляются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `app-settings`: сброс испорченного файла перестаёт быть молчаливым.
- `main-window`: автооткрытие после сброса настроек не создаёт БД автоматически.
- `sqlite-persistence`: уникальные имена резервных копий и ограничение их числа.

## Impact

- `SettingsStore.load()` сообщает, был ли сброс; `DatabaseController` показывает предупреждение и запоминает признак.
- `DatabaseController.attempt` / `openOnStartup`: автосоздание по умолчанию отключено после сброса.
- `Database.createBackup` / `migrateWithBackup`: уникальное имя и очистка старых копий.
- Тесты: `SettingsStoreTest`, `DatabaseControllerTest`, `DatabaseMigrationTest`.
- Вне рамок: настройка числа копий в интерфейсе, удаление копий вручную, смена формата настроек.
