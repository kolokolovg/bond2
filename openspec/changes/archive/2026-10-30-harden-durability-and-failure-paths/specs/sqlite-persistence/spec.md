# Spec Delta

## ADDED Requirements

### Requirement: Сохранность зафиксированных транзакций
Система SHALL выполнять транзакции данных с полной синхронизацией на диск при фиксации, чтобы зафиксированная транзакция переживала потерю питания и сбой операционной системы. Служебные соединения (проверка схемы, резервная копия, перенос WAL) данные не записывают и этому требованию не подчиняются.

#### Scenario: Режим синхронизации транзакций
- **WHEN** открывается соединение для транзакции чтения или записи
- **THEN** режим синхронизации соединения — полный

## MODIFIED Requirements

### Requirement: Резервная копия и откат при миграции существующей БД
Перед миграцией существующей БД система SHALL создать резервную копию с помощью `VACUUM INTO` рядом с исходным файлом (копия согласована с данными из WAL и не зависит от записи, выполняемой другими соединениями) и проверить её целостность. Если миграция завершилась ошибкой, система SHALL атомарно заменить файл БД копией (через временный файл рядом и атомарное перемещение) и передать вызывающему ошибку миграции с исходной причиной; прежние копии при этом SHALL NOT удаляться, кроме вытеснения по лимиту из требования «Имена и хранение резервных копий».

#### Scenario: Успешная миграция
- **WHEN** миграция существующей БД завершена успешно
- **THEN** схема актуальна, резервная копия предыдущего состояния сохранена

#### Scenario: Неудачная миграция
- **WHEN** миграция существующей БД завершилась ошибкой
- **THEN** файл БД восстановлен из резервной копии: схема и данные совпадают с состоянием до миграции (побайтное совпадение с исходным файлом не требуется), вызывающему передана ошибка миграции, прежние копии не удалены сверх лимита

#### Scenario: Сбой в середине набора миграций
- **WHEN** часть миграций набора применена, а следующая завершилась ошибкой
- **THEN** БД восстановлена к состоянию до начала всей миграции, ни одна из ранее применённых в этом запуске миграций не сохраняется

#### Scenario: Копия не прошла проверку целостности
- **WHEN** проверка целостности резервной копии не вернула «ok»
- **THEN** миграция не выполняется, БД не изменяется, возвращается ошибка

#### Scenario: Не удалось создать копию
- **WHEN** резервную копию создать не удалось
- **THEN** миграция не выполняется, БД не изменяется, возвращается ошибка

#### Scenario: Данные в WAL попадают в копию
- **WHEN** перед миграцией в WAL есть зафиксированные, но не перенесённые данные
- **THEN** резервная копия содержит эти данные

#### Scenario: Сбой замены файла при откате
- **WHEN** атомарная замена файла БД копией не удалась
- **THEN** файл БД не изменён частично, временный файл удалён, ошибка содержит путь к копии для ручного восстановления

### Requirement: Имена и хранение резервных копий
Имя резервной копии содержит метку времени; если такая копия уже существует, система SHALL выбрать свободное имя с числовым суффиксом, не перезаписывая существующую. После любой попытки миграции, успешной или неудачной, система SHALL сохранять три последние резервные копии этого файла БД (включая новую) и удалять более старые. Только что созданная копия SHALL NOT удаляться ни при каком порядке меток времени.

#### Scenario: Копия с той же меткой времени уже есть
- **WHEN** копия с такой меткой времени уже существует
- **THEN** новая копия создаётся с числовым суффиксом, существующая не изменяется, миграция выполняется

#### Scenario: Ограничение числа копий
- **WHEN** после успешной миграции у файла БД больше трёх резервных копий
- **THEN** остаются три самые новые, остальные удалены; копии других файлов и посторонние файлы не затрагиваются

#### Scenario: Ограничение числа копий после неудачной миграции
- **WHEN** миграция завершилась ошибкой и у файла БД больше трёх резервных копий
- **THEN** остаются три самые новые, включая только что созданную; остальные удалены

#### Scenario: Метки старых копий позже метки новой
- **WHEN** после попытки миграции у файла БД есть три и более копий с метками времени позже метки новой копии (например, после перевода часов назад)
- **THEN** новая копия сохранена, всего остаётся три копии: новая и две самые новые из остальных
