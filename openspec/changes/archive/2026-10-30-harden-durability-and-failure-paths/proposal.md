# Proposal

## Why

Обзор кода выявил места, где сбой оставляет приложение в плохом состоянии или ослабляет
сохранность данных: `Error` при открытии БД навсегда блокирует меню, записи WAL с
`synchronous=NORMAL` могут откатиться при потере питания, запись настроек не сбрасывается на диск,
а резервные копии при повторных сбоях миграции копятся без ограничений.

## What Changes

- Открытие, создание, миграция и закрытие БД переводят любой сбой, включая `Error`
  (кроме `VirtualMachineError`), в состояние «БД закрыта» с причиной «внутренняя ошибка», а не
  оставляют `Opening`.
- Соединения транзакций работают с `synchronous=FULL` вместо `NORMAL`.
- Резервные копии обрезаются до трёх после любой попытки миграции, в том числе неудачной.
- Запись настроек сбрасывает данные на диск (`force`) до атомарной замены; осиротевшие
  `settings-*.tmp` удаляются при чтении; файл настроек нулевой длины считается повреждённым.
- `DatabaseController.stopped` становится `volatile`.
- README: файл БД должен лежать на локальном диске.

### Принятые решения (вне изменения кода)

- Ожидание миграции до 30 с в `stop()` (поток JavaFX) **сохраняется** сознательно: прервать
  миграцию хуже, чем подождать. Случай редкий: без меню `stop()` почти не вызывается.
- Блокировка единственного экземпляра остаётся в каталоге данных. Приложение однопользовательское
  и однопроцессное; защита от нескольких профилей на одном файле БД не добавляется.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sqlite-persistence`: режим синхронизации `FULL`; обрезка копий после неудачной миграции.
- `app-settings`: запись настроек с fsync; очистка временных файлов; пустой файл — повреждение.
- `database-lifecycle`: любой сбой операции жизненного цикла даёт состояние «закрыта».

## Impact

- Код: `DatabaseService`, `SqliteSupport`, `BackupManager`, `SettingsStore`, `DatabaseController`.
- Тесты: сбой `Storage` с `UnsatisfiedLinkError`, `PRAGMA synchronous`, обрезка копий после сбоя,
  пустой файл настроек, очистка `.tmp`.
- README.
- Вне рамок: изменение ожидания в `stop()`, блокировка на уровне файла БД, проверка свободного
  места перед копией, очистка файлов `*.restore`.
