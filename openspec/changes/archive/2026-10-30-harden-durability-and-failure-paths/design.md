# Design

## Context

См. proposal.md — Why. Операции БД идут на одном потоке `bonds2-db`; состояние публикуется через
`StatePublisher`. `finish` ловит только `RuntimeException`. `SqliteSupport.properties` задаёт
`synchronous=NORMAL`. `pruneBackups` вызывается только после успешной миграции.
`SettingsStore.writeAtomically` пишет во временный файл и делает `ATOMIC_MOVE` без `force`.

## Goals / Non-Goals

**Goals:** состояние БД никогда не зависает в промежуточном; зафиксированная транзакция переживает
потерю питания; число копий ограничено при любом исходе миграции; настройки не теряются тихо.

**Non-Goals:** смена модели ожидания в `stop()`; защита от нескольких процессов на одном файле БД;
проверка свободного места; очистка `*.restore`.

## Decisions

1. **Любой сбой в `finish` даёт `Closed`.** Ловим `RuntimeException | Error`, публикуем
   `Closed(unexpected)`, возвращаем `Failed`. `VirtualMachineError` пробрасывается дальше.
   Так же в `doClose`. Альтернатива — ловить только `UnsatisfiedLinkError`: отвергнута, список
   конкретных `Error` неполон (`NoClassDefFoundError`, `ExceptionInInitializerError`).

2. **`synchronous=FULL`** только в `SqliteSupport.properties` (транзакции данных). Служебные
   соединения не меняются: они не пишут данные. Цена — скорость записи, при текущих объёмах
   незаметна. Альтернатива — оставить `NORMAL`: отвергнута, потеря последней записи при отказе
   питания неприемлема для учёта.

3. **Обрезка копий в `finally`.** `pruneBackups(absolute, backup)` вызывается после любой попытки
   миграции. Новая копия по-прежнему не удаляется. Альтернатива — обрезать при старте: отвергнута,
   лишняя точка входа.

4. **Запись настроек с `force`.** Данные пишутся через `FileChannel`, `force(true)`, затем
   `ATOMIC_MOVE`. Синхронизация каталога — только на POSIX, на Windows пропускается (каталог
   открыть как канал нельзя). Файл нулевой длины при чтении считается повреждённым: диалог
   показывается, копия `.bad-…` не создаётся. Осиротевшие `settings-*.tmp` удаляются в `load()`
   (под блокировкой экземпляра). Альтернатива — оставить пустой файл как «нет ключей»: отвергнута,
   путь к БД сбросится молча.

5. **Ожидание миграции в `stop()` сохраняется** (принято). `stopped` — `volatile`; в `shutdown()`
   комментарий поясняет, почему поток JavaFX блокируется. Альтернатива — не ждать и откатывать при
   следующем запуске: отвергнута, теряется гарантия «файл не тронут».

6. **Однопользовательский режим** (принято): блокировка остаётся в каталоге данных, README
   требует локальный диск из-за WAL.

## Risks / Trade-offs

- [`FULL` замедляет запись] → объёмы малы; при росте нагрузки пересмотреть пакетные транзакции.
- [`force` медленнее на HDD] → настройки пишутся редко.
- [Поглощение `Error` скрывает сбой] → пишется в лог уровня ERROR, `VirtualMachineError` не
  поглощается.
- [`stop()` блокирует поток JavaFX до ~65 с] → принято, случай редкий.
