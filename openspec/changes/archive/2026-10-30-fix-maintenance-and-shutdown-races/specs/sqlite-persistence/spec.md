# Spec Delta

## ADDED Requirements

### Requirement: Служебные операции не создают файл БД
Система SHALL выполнять служебные операции над БД (создание резервной копии, проверку целостности копии, чтение схемы) только над существующим файлом: если файл удалён или перемещён, операция SHALL завершаться ошибкой, а новый файл по этому пути SHALL NOT создаваться.

#### Scenario: Файл БД удалён до создания копии
- **WHEN** файл БД удалён после распознавания его состояния и до создания резервной копии
- **THEN** создание копии завершается ошибкой, пустой файл на месте БД не появляется, миграция не выполняется

#### Scenario: Копия удалена до проверки целостности
- **WHEN** файл резервной копии удалён между созданием и проверкой целостности
- **THEN** проверка завершается ошибкой, пустой файл на месте копии не появляется, миграция не выполняется

#### Scenario: Файл БД удалён до чтения схемы
- **WHEN** файл БД удалён после проверки его наличия и до чтения схемы
- **THEN** распознавание состояния завершается ошибкой, файл по этому пути не появляется

## MODIFIED Requirements

### Requirement: Резервная копия и откат при миграции существующей БД
Перед миграцией существующей БД система SHALL создать резервную копию с помощью `VACUUM INTO` рядом с исходным файлом (копия согласована с данными из WAL и не зависит от записи, выполняемой другими соединениями) и проверить её целостность; проверка SHALL начинаться с наличия файла копии. Если миграция завершилась ошибкой, система SHALL атомарно заменить файл БД копией (через временный файл рядом и атомарное перемещение) и передать вызывающему ошибку миграции с исходной причиной; данные временного файла SHALL быть сброшены на диск до перемещения, а удаление сайдкаров WAL SHALL происходить так, чтобы неудача замены не приводила к потере зафиксированных транзакций основного файла. Прежние копии SHALL NOT удаляться, кроме вытеснения по лимиту из требования «Имена и хранение резервных копий».

#### Scenario: Успешная миграция
- **WHEN** миграция существующей БД завершена успешно
- **THEN** схема актуальна, резервная копия предыдущего состояния сохранена

#### Scenario: Неудачная миграция
- **WHEN** миграция существующей БД завершилась ошибкой
- **THEN** файл БД восстановлен из резервной копии: схема и данные совпадают с состоянием до миграции (побайтное совпадение с исходным файлом не требуется), вызывающему передана ошибка миграции, прежние копии не удалены сверх лимита

#### Scenario: Сбой в середине набора миграций
- **WHEN** часть миграций набора применена, а следующая завершилась ошибкой
- **THEN** БД восстановлена к состоянию до начала всей миграции, ни одна из ранее применённых в этом запуске миграций не сохраняется

#### Scenario: Копия не прошла проверку целостности
- **WHEN** проверка целостности резервной копии не вернула «ok»
- **THEN** миграция не выполняется, БД не изменяется, возвращается ошибка

#### Scenario: Не удалось создать копию
- **WHEN** резервную копию создать не удалось
- **THEN** миграция не выполняется, БД не изменяется, возвращается ошибка

#### Scenario: Данные в WAL попадают в копию
- **WHEN** перед миграцией в WAL есть зафиксированные, но не перенесённые данные
- **THEN** резервная копия содержит эти данные

#### Scenario: Сбой замены файла при откате
- **WHEN** атомарная замена файла БД копией не удалась
- **THEN** файл БД не изменён частично, зафиксированные до попытки отката транзакции не теряются, временный файл удалён, ошибка содержит путь к копии для ручного восстановления

#### Scenario: Сброс временного файла на диск перед заменой
- **WHEN** выполняется атомарная замена файла БД копией
- **THEN** данные временного файла сброшены на диск до перемещения, чтобы потеря питания сразу после замены не оставила укороченный файл БД

#### Scenario: Неудачная замена не теряет данные из WAL
- **WHEN** на момент отката миграции в WAL основного файла есть зафиксированные, но не перенесённые данные и атомарная замена завершилась ошибкой
- **THEN** при повторном открытии БД эти данные доступны: они перенесены в основной файл или остались в неповреждённом WAL
