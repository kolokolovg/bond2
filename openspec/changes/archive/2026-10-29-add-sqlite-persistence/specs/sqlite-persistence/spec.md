# Spec Delta

## Purpose
Определяет поведение локального хранилища на SQLite: инициализацию и миграции схемы и атомарность операций при параллельной работе нескольких потоков.

## ADDED Requirements

### Requirement: Инициализация и миграции схемы
При запуске приложения система SHALL открыть (или создать) файл БД SQLite и привести схему к актуальной версии, применяя ещё не применённые миграции строго по порядку версий.

#### Scenario: Первый запуск
- **WHEN** файла БД не существует
- **THEN** файл создаётся и применяются все миграции, версия схемы становится актуальной

#### Scenario: Повторный запуск
- **WHEN** БД уже содержит актуальную версию схемы
- **THEN** миграции не применяются повторно, данные не изменяются

#### Scenario: Сбой миграции
- **WHEN** миграция завершается ошибкой
- **THEN** запуск хранилища завершается ошибкой, частично применённые изменения этой миграции откатываются

### Requirement: Атомарность единицы работы
Система SHALL выполнять группу операций с БД как единую транзакцию: либо все изменения фиксируются, либо ни одно.

#### Scenario: Успешная транзакция
- **WHEN** единица работы завершается без ошибки
- **THEN** все её изменения сохранены и видны последующим операциям

#### Scenario: Ошибка внутри транзакции
- **WHEN** в ходе единицы работы возникает исключение
- **THEN** все изменения этой единицы откатываются, исключение передаётся вызывающему

### Requirement: Корректность при параллельной работе
Система SHALL корректно обрабатывать одновременные транзакции из нескольких потоков: изменения не теряются, промежуточные состояния чужих незавершённых транзакций не видны, кратковременные блокировки БД не приводят к ошибке.

#### Scenario: Параллельные конкурирующие записи
- **WHEN** несколько потоков одновременно инкрементируют одно и то же значение в БД, каждый в своей транзакции
- **THEN** итоговое значение равно числу успешно завершённых инкрементов (без потерянных обновлений)

#### Scenario: Чтение во время записи
- **WHEN** один поток выполняет незавершённую транзакцию записи, а другой читает
- **THEN** читающий видит только зафиксированные данные и не блокируется надолго

#### Scenario: Кратковременная занятость БД
- **WHEN** запись ожидает освобождения блокировки БД в пределах настроенного таймаута
- **THEN** операция дожидается и завершается успешно, а не падает сразу с ошибкой занятости

#### Scenario: Превышение времени ожидания
- **WHEN** блокировка не освобождается за настроенный таймаут
- **THEN** операция завершается явной ошибкой, транзакция откатывается
