# Proposal

## Why

Приложению нужно хранилище данных. SQLite — встраиваемая БД без отдельного сервера. Поскольку GUI-поток JavaFX и фоновые задачи будут работать с БД параллельно, нужна единая инфраструктура с гарантированной атомарностью операций, иначе возможны потерянные обновления, частичные записи и ошибки `SQLITE_BUSY`.

## What Changes

- Добавить зависимости `sqlite-jdbc` и Flyway (JDBC, без ORM).
- Добавить слой доступа к SQLite: настройка соединений (WAL, `busy_timeout`, внешние ключи), расположение файла БД.
- Добавить версионируемые миграции схемы (Flyway), применяемые при старте; на этом этапе — только служебная схема/первая пустая миграция без доменных таблиц.
- Добавить транзакционный API: выполнение единицы работы атомарно (commit при успехе, rollback при исключении) и безопасное при параллельных вызовах из нескольких потоков.
- Доменные сущности (облигации и т.п.) и репозитории **не** входят в изменение.

## Capabilities

### New Capabilities
- `sqlite-persistence`: хранение данных в локальной SQLite-БД с автоматическими миграциями и атомарными транзакциями при параллельной работе.
