## Why

Ревью кода выявило четыре риска для данных пользователя: удалённый при работе файл БД молча пересоздаётся пустым; диалог миграции может всплыть во время выхода; восстановление после неудачной миграции неатомарно; резервная копия через `Files.copy` не защищена от записи между переносом WAL и копированием.

## What Changes

- Транзакции открывают соединение без флага создания файла: если файл БД удалён или перемещён при открытой БД, транзакция завершается `PersistenceException`, пустой файл не создаётся.
- `DatabaseController` не показывает диалог миграции, если выход уже начат или приложение остановлено.
- Откат после неудачной миграции выполняется через временный файл рядом с БД и `ATOMIC_MOVE`.
- Резервная копия перед миграцией создаётся командой `VACUUM INTO` вместо `wal_checkpoint` + `Files.copy`.

Несовместимых изменений публичного API нет. Формат имён копий (`.bak-<метка>[-N]`) и их число (3) не меняются.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sqlite-persistence`: добавляется требование «Транзакции не создают файл БД»; требование «Резервная копия и откат при миграции существующей БД» уточняет способ создания копии и атомарность отката.
- `main-window`: требование «Подтверждение миграции при открытии БД» дополняется сценарием выхода до показа диалога.

## Impact

- Код: `persistence/SqliteSupport` (`properties`), `persistence/Database` (`run`), `persistence/BackupManager` (`createBackup`, `restore`), `ui/DatabaseController` (`askAboutMigration`).
- Тесты: `DatabaseTest`, `DatabaseMigrationTest`, `DatabaseControllerTest`.
- Зависимости не меняются.

Вне рамок: сброс настроек по одному битому ключу, синхронный `stop()` в потоке JavaFX, обработка `Error` в `DatabaseService`, `fsync` настроек, предупреждение о сетевых ФС.
