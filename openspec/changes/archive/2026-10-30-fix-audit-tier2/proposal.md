# Proposal

## Why

Тир 2 аудита кода: три латентные дыры контрактов владения файлом БД. Статические операции `Database` (создание, инициализация, миграция с резервной копией) никак не координируются с открытыми экземплярами — откат миграции может заменить файл под живым соединением (Database.java:67 против статических операций на 97/113, 186/191, 224/230). При внутренней ошибке закрытия `DatabaseService.doClose` выбрасывает хендл БД без попытки закрыть его повторно (DatabaseService.java:315–331), а `Error` подписчика при публикации состояния «открыта» оставляет БД в поле-владельце навсегда: `close()` после этого отвергается до самой остановки (DatabaseService.java:370–371, StatePublisher.java:161). Сегодня большинство путей недостижимо из интерфейса, но API этого не запрещает, а ошибки подписчика и внутренней ошибки закрытия достижимы и сейчас.

## What Changes

- `Database` ведёт реестр открытых экземпляров по нормализованному абсолютному пути: `create`, `initialize` и `migrateWithBackup` отказывают fail-fast без касания файла, если на том же файле есть живой экземпляр; контракт исключительного владения задокументирован в джавадоке.
- `doClose` при внутренней ошибке закрытия (не `PersistenceException`) делает тихую повторную попытку закрыть БД перед отчётом об ошибке — соединение не остаётся висеть у драйвера.
- Публикация состояния «открыта» защищена: `Error` подписчика закрывает полученную БД тихо, освобождает поле-владелец и пробрасывается дальше — существующая страховка `submit` публикует «закрыта (внутренняя ошибка)», сервис продолжает работать.
- Закрыты тестовые пробелы: отказ реестра, внутренняя ошибка закрытия с реальной (не помечающей) БД, ошибка подписчика именно на публикации «открыта» (существующий тест покрывает только «открывается»).

## Capabilities

### New Capabilities

_Нет: расширяются существующие возможности._

### Modified Capabilities

- `sqlite-persistence`: новое требование «Исключительное владение файлом при служебных операциях» — создание, инициализация и миграция с резервной копией отказывают при открытом экземпляре того же файла.
- `database-lifecycle`: новые требования «Сбой закрытия не оставляет БД без владельца» и «Ошибка подписчика при публикации открытой БД не теряет БД».

## Impact

- Код: `persistence/Database.java`, `dbservice/DatabaseService.java`; тесты `persistence/DatabaseTest.java`, `dbservice/DatabaseServiceTest.java`; README (раздел о владельце файла БД).
- Несовместимых изменений для приложения нет: новые отказы API срабатывают только на ошибках программиста; `PersistenceException` — уже обрабатываемый тип.
- Вне рамок: остальные находки аудита — тир 3 (таймауты shutdownAsync, таксономия ошибок SQLite, дубликаты подписок, чтение настроек на FX-потоке, shutdown hook, файловые диалоги, UI-гарды) и тир 4 (задачи сборки `downloadOpenjml`, свойства Gradle).
