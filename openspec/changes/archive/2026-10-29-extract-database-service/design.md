## Context

`DatabaseController` совмещает машину состояний БД, JavaFX-свойства (`stateProperty`, `statusProperty`), диалоги и выход из приложения. Фоновую работу ему даёт `Background` (реализация `FxBackground` на `javafx.concurrent.Task`), а результаты возвращаются в поток JavaFX. Файл БД не имеет одного владельца: `close()` вызывается из потока JavaFX, а при истечении срока ожидания блокировка экземпляра освобождается, пока демон-поток ещё работает с файлом. `Database` и пакет `persistence` уже не зависят от JavaFX и остаются без изменений по контракту. В схеме пока одна таблица `app_info`, доменных сервисов нет.

## Goals / Non-Goals

**Goals:**
- Ядро жизненного цикла БД без `javafx.*`, тестируемое без `FxToolkit`.
- Один владелец файла: все операции жизненного цикла строго последовательны.
- Остановка, после которой блокировка экземпляра освобождается только когда с файлом никто не работает (кроме явного таймаута для открытия и создания).
- Состояние публикуется через `Flow.Publisher`; UI подписывается.

**Non-Goals:**
- Восстановление после убийства процесса посреди миграции (метка «миграция начата»).
- Доменные сервисы и таблицы.
- Изменение `Database`, схемы, формата настроек.

## Decisions

### 1. Сервис с одним потоком жизненного цикла
`DatabaseService` владеет `ExecutorService` из одного потока (не демон, имя `bonds2-db`). Все операции жизненного цикла (`open`, `create`, `migrate`, `close`, `shutdown`) идут через него и возвращают `CompletableFuture`. Допустимость операции проверяется на этом потоке по текущему состоянию, поэтому гонок между `OPENING` и `MIGRATING` нет.
- Альтернатива: оставить `Background` и вынести только состояние. Отвергнута: остаётся два владельца (UI-поток и фон), гонка при выходе не уходит.
- Альтернатива: `synchronized` и общий пул. Отвергнута: порядок операций неявный, `awaitTermination` недоступен.

### 2. Состояние как sealed-иерархия, публикация через `Flow.Publisher`
`DbState` становится неизменяемым снимком (запись или sealed interface): `Closed(reason, message)`, `Opening(kind)`, `AwaitingMigration`, `Migrating`, `Open(path)`. Публикация через `SubmissionPublisher`-подобную реализацию на потоке жизненного цикла; подписчик получает текущее состояние при подписке, затем изменения по порядку. Адаптер UI переводит их в `Platform.runLater` и обновляет `ReadOnlyObjectProperty`.
- Альтернатива: `Consumer<DbState>`. Отвергнута пользователем: нужен полный `Flow` с обратным давлением и стандартным контрактом.
- Риск: `SubmissionPublisher` использует общий `ForkJoinPool` и буфер; при медленном подписчике `submit` блокируется. Подписчик UI только ставит задачу в очередь JavaFX, поэтому блокировки нет; в design фиксируется `offer` с отбрасыванием устаревшего состояния не допускается, так как терялись бы переходы. Размер буфера выбирается с запасом, а подписчик UI быстрый.

### 3. Двухфазная миграция
`open()` завершается состоянием `AwaitingMigration` без изменения файла. UI показывает диалог и вызывает `migrate()` или `declineMigration()`. Сервис не вызывает диалоги.
- Альтернатива: колбэк `Predicate<String> confirmMigration` в сервисе. Отвергнута: синхронное ожидание решения блокирует поток жизненного цикла и смешивает слои.
- Состояние `AwaitingMigration` блокирует остановку (как и `Migrating`), пока решение не принято: так диалог не оказывается над закрывающимся приложением.

### 4. Остановка и срок ожидания
`shutdown(Duration)` ставит флаг остановки, отклоняет новые операции, ждёт `awaitTermination` не дольше срока и закрывает БД. Отказ для `Migrating` и `AwaitingMigration`: возвращается результат «занято»; UI показывает «Идёт миграция» и не закрывает окно. Для `Opening` срок 30 с, по истечении `shutdownNow` не вызывается: операция короткая, откат безопасен (`create` удаляет созданный файл, `initialize` возвращает файл к пустому), а запоздавшая БД закрывается сама на потоке сервиса. Поток при этом не демон только пока не истёк срок; после срока он помечается завершающимся, а процесс завершается через `Platform.exit` и `System.exit` не требуется, потому что поток закроет БД и завершится самостоятельно.
- Альтернатива: ждать без срока. Отвергнута пользователем: зависшая операция должна позволять выйти.
- Остаточный риск: после срока блокировка экземпляра освобождается, пока запоздавшая операция ещё может писать. Принимается для открытия и создания: они редкие, короткие и обратимые; миграция защищена запретом выхода.

### 5. Диалог миграции и выход
Адаптер знает, что диалог открыт (флаг в потоке JavaFX), и в `requestExit` показывает «Идёт миграция» или ничего не делает, пока диалог открыт. Иначе поверх диалога появлялся бы второй.

### 6. Файловые операции и платформы
Новых файловых операций нет. `InstanceLock` освобождается после `shutdown` как раньше (`FileChannel.tryLock`: Linux, macOS, Windows ведут себя одинаково для одного процесса). Порядок «сервис остановлен, затем блокировка» сохраняется в `MainWindowApp.stop`.

### 7. Поведение при сбое
- Сбой открытия: состояние `Closed` с причиной, файл не изменён (кроме отката `create` и `initialize`, как раньше).
- Сбой миграции: `migrateWithBackup` восстанавливает файл из копии; сервис публикует `Closed(reason=миграция)` и сообщение с путём к копии.
- Исключение в операции: поток жизненного цикла не завершается; результат `Failed` с причиной «внутренняя ошибка».
- Убийство процесса посреди миграции: вне рамок (см. Non-Goals), поведение как сейчас.

## Risks / Trade-offs

- [Рефакторинг без видимого результата] -> Закрывает реальные дефекты (гонка при выходе, блокирующий `close()`) и готовит почву для доменных сервисов.
- [Объём переработки тестов: `DatabaseControllerTest`, `FxBackgroundTest`, `MainWindowAppTest`] -> Тесты ядра пишутся без JavaFX; UI-тесты сокращаются до проверки адаптера.
- [Покрытие и pitest на новом коде] -> Новые классы входят в проверки `check` и `pitest`; пороги из `gradle.properties` не снижаются.
- [Неснятая блокировка по таймауту] -> см. решение 4, остаточный риск принят.

## Migration Plan

Поведенческая миграция данных не нужна. Шаги: добавить ядро и тесты, перевести контроллер на сервис, удалить `Background` и `FxBackground`, обновить тесты UI. Откат: вернуть предыдущий коммит; формат файлов и настроек не меняется.
