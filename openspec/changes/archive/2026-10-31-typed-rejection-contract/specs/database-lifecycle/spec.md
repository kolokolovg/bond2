# Spec Delta

## ADDED Requirements

### Requirement: Типизированная причина отклонения

Результат отклонения операции жизненного цикла SHALL нести причину отклонения отдельным значением наряду с текстом сообщения: недопустимость операции в текущем состоянии, начатая остановка сервиса, существование файла (для создания). Потребитель результата SHALL различать эти причины по значению причины, без разбора текста сообщения. Текст сообщения предназначен пользователю и MAY изменяться независимо от значения причины.

#### Scenario: Отклонение из-за состояния

- **WHEN** операция запускается в состоянии, в котором она недопустима (например, открытие при идущей миграции)
- **THEN** результат отклонения несёт причину «недопустима в текущем состоянии», различимую по значению причины без разбора текста сообщения

#### Scenario: Отклонение после начала остановки

- **WHEN** операция отклоняется из-за начавшейся остановки сервиса
- **THEN** результат отклонения несёт причину «остановка сервиса», различимую по значению причины

#### Scenario: Отклонение создания из-за существующего файла

- **WHEN** создание БД отклоняется, потому что файл уже существует
- **THEN** результат отклонения несёт причину «файл существует», различимую по значению причины, и файл не изменяется

#### Scenario: Независимость причины от формулировки сообщения

- **WHEN** формулировка пользовательского текста отклонения изменяется
- **THEN** классификация причины потребителем не изменяется
