# Spec Delta

## ADDED Requirements

### Requirement: Единственная БД приложения
Все операции SHALL выполняться над единственным файлом БД в каталоге данных приложения; путь к БД не настраивается и не выбирается. Если каталог данных отсутствует, он создаётся. Файл по любому другому пути SHALL NOT открываться и изменяться.

#### Scenario: Каталог данных отсутствует
- **WHEN** при первом открытии нет ни файла, ни каталога данных
- **THEN** каталог и файл БД создаются, применяется весь набор миграций

#### Scenario: Файл вне каталога данных
- **WHEN** файл с базой приложения лежит вне каталога данных
- **THEN** приложение его не открывает и не изменяет

### Requirement: Миграции набора в одной транзакции
Неприменённые миграции SHALL применяться строго по порядку версий в одной транзакции SQLite вместе с записями истории миграций. Сбой любой миграции SHALL откатывать всю транзакцию: ни одна миграция набора не остаётся применённой, файл БД остаётся до-миграционным.

#### Scenario: Успешный набор
- **WHEN** применяются несколько неприменённых миграций
- **THEN** применены все, история миграций содержит каждую

#### Scenario: Сбой в середине набора
- **WHEN** вторая миграция набора завершается ошибкой
- **THEN** транзакция откачена: ни одна миграция набора не применена, файл БД до-миграционный, история не содержит записей набора

#### Scenario: Сбой после выполнения миграции
- **WHEN** миграция выполнена, но запись истории не удаётся
- **THEN** транзакция откатывается вместе с изменениями этой миграции

### Requirement: Резервная копия по указанию пользователя
Система SHALL создавать резервную копию единственной БД по выбранному пользователем пути командой `VACUUM INTO` с последующей проверкой целостности. Копия принадлежит пользователю: приложение SHALL NOT учитывать, ограничивать или удалять её.

#### Scenario: Успешная копия
- **WHEN** пользователь указывает место и подтверждает копирование
- **THEN** копия создана, прошла проверку целостности, пользователю сообщён итог с путём

#### Scenario: Сбой копирования
- **WHEN** копирование завершается ошибкой (нет места, файл занят)
- **THEN** пользователю сообщена классифицированная причина, частично записанный файл удалён

### Requirement: Восстановление из копии вручную
Приложение SHALL NOT содержать механизма восстановления из резервных копий. Восстановление выполняется пользователем вручную при закрытом приложении; процедура описана в README.

#### Scenario: Восстановленная БД открывается
- **WHEN** пользователь заменил файл БД копией при закрытом приложении и запустил его
- **THEN** БД распознаётся и открывается по общим правилам версии схемы

## MODIFIED Requirements

### Requirement: Резервная копия перед миграцией существующей БД
Перед миграцией существующей БД система SHALL создать одну служебную копию фиксированного имени в каталоге данных приложения: копия создаётся командой `VACUUM INTO` во временный файл, проверяется на целостность и атомарно заменяет прежнюю служебную копию. Если копию создать или проверить не удалось, миграция SHALL NOT выполняться, файл БД не изменяется, вызывающий получает ошибку.

#### Scenario: Успешная миграция
- **WHEN** миграция существующей БД завершена успешно
- **THEN** схема актуальна, служебная копия предыдущего состояния сохранена под фиксированным именем

#### Scenario: Копия не прошла проверку целостности
- **WHEN** проверка целостности копии не вернула «ok»
- **THEN** миграция не выполняется, БД не изменяется, временный файл удалён, возвращается ошибка

#### Scenario: Не удалось создать копию
- **WHEN** резервную копию создать не удалось
- **THEN** миграция не выполняется, БД не изменяется, возвращается ошибка

#### Scenario: Данные в WAL попадают в копию
- **WHEN** перед миграцией в WAL есть зафиксированные, но не перенесённые данные
- **THEN** служебная копия содержит эти данные

### Requirement: Служебные операции не создают файл БД
Система SHALL выполнять служебные операции над БД (создание резервной копии, проверку целостности копии, чтение схемы, чтение истории миграций, применение миграций, инициализацию схемы) только над существующим файлом: если файл удалён или перемещён, операция SHALL завершаться ошибкой, а новый файл по этому пути SHALL NOT создаваться.

#### Scenario: Файл БД удалён до создания копии
- **WHEN** файл БД удалён после распознавания его состояния и до создания резервной копии
- **THEN** создание копии завершается ошибкой, пустой файл на месте БД не появляется, миграция не выполняется

#### Scenario: Копия удалена до проверки целостности
- **WHEN** файл резервной копии удалён между созданием и проверкой целостности
- **THEN** проверка завершается ошибкой, пустой файл на месте копии не появляется, миграция не выполняется

#### Scenario: Файл БД удалён до чтения схемы
- **WHEN** файл БД удалён после проверки его наличия и до чтения схемы
- **THEN** распознавание состояния завершается ошибкой, файл по этому пути не появляется

#### Scenario: Файл БД удалён до чтения истории миграций
- **WHEN** файл БД удалён после чтения схемы, но до чтения истории миграций
- **THEN** распознавание состояния завершается ошибкой, файл по этому пути не появляется

#### Scenario: Файл БД удалён до применения миграций
- **WHEN** файл БД удалён после успешной проверки резервной копии, но до применения миграций
- **THEN** применение миграций завершается ошибкой, пустой файл на месте БД не появляется

#### Scenario: Пустой файл удалён до инициализации
- **WHEN** пустой файл БД удалён после распознавания его состояния, но до инициализации схемы
- **THEN** инициализация завершается ошибкой, новый файл по этому пути не создаётся

## REMOVED Requirements

### Requirement: Инициализация и миграции схемы
**Reason**: путь из настроек не существует, операции разделены иначе: единственная БД создаётся при открытии, набор миграций применяется одной транзакцией.
**Migration**: см. «Единственная БД приложения» и «Миграции набора в одной транзакции» в этой дельте; порядок версий сохранён.

### Requirement: Создание новой БД
**Reason**: отдельная операция создания по выбранному пути не существует; создание происходит автоматически при открытии отсутствующей единственной БД.
**Migration**: действия пользователя не требуется: файл создаётся при первом открытии.

### Requirement: Откат из резервной копии при неудачной миграции
**Reason**: откат обеспечивает единая транзакция набора миграций: сбой оставляет файл до-миграционным без какого-либо восстановления.
**Migration**: восстановление из копии — вручную, при закрытом приложении (см. «Восстановление из копии вручную»).

### Requirement: Отсутствие отката при удалённом основном файле
**Reason**: восстановления не существует; сбой миграции не изменяет файл в любой ситуации.
**Migration**: копия для ручного восстановления — служебная копия фиксированного имени.

### Requirement: Имена и хранение резервных копий
**Reason**: хранится одна служебная копия фиксированного имени, перезаписываемая перед каждой миграцией; поколений, меток времени и лимитов нет.
**Migration**: прежние копии вида `*.bak-*` приложением не удаляются и остаются пользователю.

### Requirement: Очистка временных файлов отката
**Reason**: временных файлов отката не существует — откат миграции выполняется транзакцией SQLite.
**Migration**: оставшиеся от прошлых версий файлы `*.restore` приложением не трогаются.
