# Spec Delta

## ADDED Requirements

### Requirement: Единственная БД в операциях сервиса
Операции жизненного цикла SHALL адресоваться только единственному файлу БД приложения; операции с произвольным путём SHALL NOT предоставляться. Открытие отсутствующего файла SHALL создавать БД с актуальной схемой и открывать её.

#### Scenario: Файл отсутствует
- **WHEN** запрашивается открытие, а файла БД нет
- **THEN** создаётся БД с актуальной схемой и открывается

#### Scenario: Единственный файл операций
- **WHEN** выполняется любая операция жизненного цикла
- **THEN** она адресована только файлу БД из каталога данных приложения

### Requirement: Резервное копирование как операция сервиса
Резервное копирование SHALL выполняться операцией сервиса жизненного цикла: строго по одному с другими операциями и только при открытой БД. Отклонение копирования SHALL подчиняться общим правилам отклонений операций.

#### Scenario: Копирование упорядочено с операциями
- **WHEN** копирование запрошено, пока выполняется другая операция
- **THEN** копирование начинается только после её завершения

#### Scenario: Копирование при неоткрытой БД
- **WHEN** копирование запрошено, а БД не открыта
- **THEN** запрос отклонён с типизированной причиной отклонения

### Requirement: Типизированные причины отклонения
Результат отклонения операции жизненного цикла SHALL нести причину отклонения отдельным значением наряду с текстом сообщения: недопустимость операции в текущем состоянии или начатая остановка сервиса. Потребитель результата SHALL различать эти причины по значению, без разбора текста сообщения.

#### Scenario: Отклонение из-за состояния
- **WHEN** операция запускается в состоянии, в котором она недопустима
- **THEN** результат отклонения несёт причину «недопустима в текущем состоянии», различимую по значению причины

#### Scenario: Отклонение после начала остановки
- **WHEN** операция отклоняется из-за начавшейся остановки сервиса
- **THEN** результат отклонения несёт причину «остановка сервиса», различимую по значению причины

#### Scenario: Независимость причины от формулировки сообщения
- **WHEN** формулировка пользовательского текста отклонения изменяется
- **THEN** классификация причины потребителем не изменяется

## REMOVED Requirements

### Requirement: Типизированная причина отклонения
**Reason**: причина «файл существует» исчезает вместе с операцией создания по произвольному пути; остаются две причины — недопустимость состояния и остановка сервиса.
**Migration**: потребители различают причины по значению, как прежде; замена требования — «Типизированные причины отклонения» в этой же дельте.
