## Why

Два места могут привести к потере или порче данных. Файл SQLite без таблиц, но с views, triggers, индексами или заголовочными значениями считается пустым и инициализируется; при неудачной миграции такой файл обрезается до 0 байт. Каталог данных на Windows лежит в Roaming-профиле (`%APPDATA%`), который синхронизируется между машинами, а это опасно для SQLite в режиме WAL. Кроме того, относительное значение `XDG_DATA_HOME` даёт пути, зависящие от рабочего каталога, и ломает блокировку единственного экземпляра.

## What Changes

- Файл считается пустым (`EMPTY`) только если он имеет 0 байт либо `sqlite_master` не содержит ни одной записи и при этом `application_id = 0` и `user_version = 0`. Иначе файл без истории миграций приложения — чужая база (`FOREIGN`) и не изменяется.
- **BREAKING**: на Windows каталог данных — `%LOCALAPPDATA%\bonds2` (запасной вариант `~/AppData/Local`) вместо `%APPDATA%\bonds2`. Перенос данных из старого каталога не выполняется; версия `0.1.0` не выпускалась.
- Переменные окружения `XDG_DATA_HOME` и `LOCALAPPDATA` используются, только если значение непустое, корректное и абсолютное; иначе применяется значение по умолчанию.
- README обновляется: определение пустого файла и таблица путей.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sqlite-persistence`: изменяется требование «Распознавание пустого и чужого файла»; добавляется требование «Каталог данных приложения» (расположение по ОС, проверка переменных окружения).

## Impact

- Код: `persistence/Database.java` (`inspect`, `userTables`), `persistence/DataDirectory.java`.
- Тесты: `DatabaseTest`, `DatabaseControllerTest` (при необходимости), `DataDirectoryTest`.
- Документация: `README.md`.
- Совместимость: пользователи Windows с данными в `%APPDATA%\bonds2` должны сами указать путь в настройках; отдельной миграции нет.
