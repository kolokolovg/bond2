## Context

`Database.inspect` определяет состояние файла: 0 байт — `EMPTY`; иначе `userTables()` выбирает записи `sqlite_master` с `type='table'` без `sqlite_*`. Пустой список даёт `EMPTY`, а `initialize` при ошибке миграции вызывает `resetToEmpty` и обрезает файл до 0 байт. Так чужой файл с одними views, triggers или индексами может быть уничтожен.

`DataDirectory.appDirectory` на Windows берёт `APPDATA` (Roaming), а на Linux — `XDG_DATA_HOME`, проверяя только непустоту. Тот же каталог содержит БД с WAL, настройки и `bonds2.lock`.

## Goals / Non-Goals

**Goals:**
- Исключить обрезку файла, содержащего какие-либо объекты схемы или метки приложения.
- Убрать зависимость путей от рабочего каталога и от Roaming-профиля.

**Non-Goals:**
- Перенос данных из `%APPDATA%\bonds2`.
- Резервная копия перед инициализацией: после ужесточения она не нужна, так как пустой файл не содержит данных.
- Изменение логики миграций, резервных копий, блокировки экземпляра.

## Decisions

**1. Пустота по `sqlite_master` целиком и заголовочным значениям.**
Вместо `userTables()` проверяются три условия: `SELECT count(*) FROM sqlite_master = 0`, `PRAGMA application_id = 0`, `PRAGMA user_version = 0`. Наличие `flyway_schema_history` по-прежнему определяется отдельно по имени таблицы. Порядок: 0 байт → `EMPTY`; есть `flyway_schema_history` → разбор по истории миграций; пустой `sqlite_master` с нулевыми заголовочными значениями → `EMPTY`; иначе `FOREIGN`.
Альтернатива — резервная копия перед `initialize`: сложнее, расходует диск и лишь смягчает последствия, а не исключает их.
Альтернатива — не обрезать при ошибке, а оставить как есть: частично применённая схема помешает повторной попытке.

**2. Соединение для проверки остаётся служебным** (`maintenanceProperties`: без WAL, без изменения файла). Чтение `PRAGMA application_id` и `user_version` файл не меняет.

**3. Единый помощник «переменная окружения как абсолютный путь».**
В `DataDirectory` выделяется метод, который возвращает `Path`, только если значение непустое, разбирается через `Path.of` (с обработкой `InvalidPathException`) и абсолютно; иначе пусто. Используется для `XDG_DATA_HOME` и `LOCALAPPDATA`. Правило совпадает с `Settings.parseDatabasePath`, но пути не завязаны на `settings`, поэтому логика не дублируется через зависимость, а остаётся отдельным небольшим методом.

**4. Windows: `LOCALAPPDATA`, без миграции.**
Выбран вариант без переноса: версия `0.1.0` не выпускалась, пользователей с данными нет. Запасной вариант — `home/AppData/Local`.

## Risks / Trade-offs

- [SQLite без таблиц, но с `application_id` или `user_version`, раньше инициализировался, теперь отклоняется] → осознанное ужесточение: безопаснее; README уточняется.
- [Пользователь Windows с данными в `%APPDATA%\bonds2` потеряет видимость данных] → риск принят; путь можно задать в настройках.
- [Пустой SQLite с `sqlite_sequence` или `sqlite_stat1` теперь отклоняется] → такие файлы появляются только после использования БД, поэтому считаются чужими.
