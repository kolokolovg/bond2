# Proposal

## Why

Тир 4 аудита — сборочная обвязка. Задача `downloadOpenjml` залипает навсегда: прерванная распаковка оставляет целевой каталог, `onlyIf { !home.asFile.exists() }` (build.gradle.kts:177) с этого момента пропускает задачу, и каждый следующий `openjmlProve` падает загадочной ошибкой битого бинарника вместо перезагрузки; контрольной суммы у скачиваемого архива нет. Пороги проверок читаются `.get()` на свойствах (строки 110, 129, 158): отсутствие свойства роняет конфигурацию любой задачи непрозрачным исключением вместо значения по умолчанию. Версии инструментов (pitest 1.30.1, плагин pitest-junit5 1.2.3, SpotBugs 4.10.5 — строки 121/122/137) захардкожены в скрипте мимо каталога `libs.versions.toml`, а связка pitest-junit5 1.2.3 с JUnit 6.x — скрытая точка будущей поломки. Перечни исключений JaCoCo и pitest расходятся неявно: два гейта качества по-разному определяют «UI-клей» без зафиксированного обоснования.

## What Changes

- `downloadOpenjml` распаковывает во временный каталог `build/` и атомарно перемещает результат в `tools/`: прерванная попытка не оставляет частичного состояния, повторный запуск выполняет загрузку заново; готовность определяется наличием инструмента, а не существованием каталога.
- Необязательное свойство `openjml.sha256`: при задании контрольная сумма архива проверяется до распаковки, несовпадение — внятная ошибка без касания `tools/`; без свойства целостность гарантирует распаковка (повреждённый архив падает, ничего не оставляя).
- Пороги `coverage.minLine` и `mutation.threshold` получают значения по умолчанию в скрипте (`getOrElse`): отсутствие свойства больше не роняет конфигурацию.
- Версии OpenJML, pitest, плагина pitest-junit5 и SpotBugs переезжают в каталог версий `libs.versions.toml`; `-Popenjml.version` остаётся точечным переопределением поверх значения из каталога; ключ кэша CI учитывает каталог.
- Перечни исключений JaCoCo и pitest становятся именованными константами скрипта с комментариями, фиксирующими политику каждого гейта; расхождение остаётся сознательным и объяснённым.
- Версия плагина pitest-junit5 обновляется до совместимой с JUnit 6.x (с проверкой мутационного прогона); связка фиксируется комментарием в каталоге версий.

## Capabilities

### New Capabilities

_Нет: расширяются существующие возможности._

### Modified Capabilities

- `java-gradle-build`: новые требования «Устойчивость конфигурации к отсутствию свойств» и «Версии инструментов в каталоге версий».
- `code-verification`: новое требование «Воспроизводимая загрузка инструмента верификации».

## Impact

- Код: `build.gradle.kts`, `gradle/libs.versions.toml`, `gradle.properties`, `.github/workflows/ci.yml` (ключ кэша OpenJML); README при упоминании свойств сборки.
- Поведение сборки: отсутствие опциональных свойств перестаёт быть фатальным; `tools/` больше не может оказаться в залипшем частичном состоянии; для разработчика без изменений, кроме первого скачивания.
- Вне рамок: содержательная политика порогов покрытия и мутаций (значения не меняются); выравнивание перечней исключений гейтов (расхождение сохранено как осознанное); тиры 1–3 аудита — уже закрыты (`52e27a7`, `2315245`).
