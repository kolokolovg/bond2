# Design

## Context

Три удаляемых элемента — единственные члены production-классов без production-потребителей (см. proposal.md — Why). Все тесты, которые их используют, лежат в тех же пакетах, что и сами классы, поэтому доступны пакетно-приватные альтернативы. Хранилище, миграции и файловые операции не затрагиваются; поведение при сбое не меняется.

## Goals / Non-Goals

**Goals:**

- Сузить поверхность production-кода до используемого production-потребителями.
- Разорвать зависимость слоя настроек от слоя хранения (`Settings → DataDirectory`).
- Сохранить неизменным наблюдаемое поведение и его тестовое покрытие.

**Non-Goals:**

- Переработка test-only API `SettingsDialog` и тестовой инфраструктуры UI.
- Изменение классификации сбоев или текстов сообщений.

## Decisions

### 1. Поведение «пустой путь = путь по умолчанию» остаётся в `DatabaseController.open`

`Settings` после удаления метода хранит только значение (`null` = не задан); резолв умолчания — в `DatabaseController.open` (уже реализовано, `defaultDatabaseFile`). Тесты `SettingsTest.missingPathResolvesToDefaultDatabaseFile` и `configuredPathResolvesToItself` удаляются: они проверяли дублирующий резолв; семантика «null = по умолчанию» остаётся покрытой `defaultsUseDefaultPathAndEnableAutoOpen` (assert `databasePath() == null`), поведение резолва — тестами контроллера на `defaultFile()`, включая граничный случай авто создания по умолчанию.

- Альтернатива: оставить метод, перенеся его в тестовый helper — отвергнута: дублирование резолва сохраняется, зависимость настроек от хранения остаётся.

### 2. Требование «Занятость SHALL помечаться повторимой причиной» остаётся выполненным

Пометка — это сама причина `REASON_BUSY` («БД занята»), выделенная в классификации, с подсказкой повтора в сообщении; `retryable()` — предикат над этой пометкой без потребителей. Утверждение `DatabaseServiceTest:342` переписывается на равенство причины `REASON_BUSY`; тесты предиката в `OpenFailuresTest` удаляются вместе с ним.

- Альтернатива: сохранить `retryable()` как реализацию требования — отвергнута: требование описывает классификацию результата, а не метод; неиспользуемый метод не может реализовывать поведение.

### 3. Тесты `SqliteSupport` переходят на существующие фабрики

Перегрузка `maintenanceProperties(Duration)` удаляется; проверки свойств используют `maintenanceProperties()` (таймаут для них не важен), сценарии с коротким `busy_timeout` — пакетно-приватную `existingFileProperties(Duration)` напрямую. Семейная симметрия с production-используемой `checkpointProperties(Duration)` сохраняется семантически: разный таймаут нужен только чекпойнту.

- Альтернатива: оставить перегрузку для симметрии — отвергнута: симметрия с неиспользуемым членом не ценность, а скрытая поверхность.

## Risks / Trade-offs

- [Потеря покрытия семантики «null = путь по умолчанию»] → до удаления проверяется наличие покрывающих тестов контроллера (автооткрытие по умолчанию, авто создание по умолчанию); при зазоре — тест добавляется в группу задач Settings.
- [pitest: удаление протестированного кода меняет долю мутантов] → удаляются и мутанты, и их тесты; доля не должна упасть — проверяется прогоном.
- [Совпадение файлов с change `typed-rejection-contract`] → правки в разных строках; порядок применения любой, конфликт решается тривиальной перебазировкой.

Файловые операции, платформы (Linux/macOS/Windows), хранение и откат не затрагиваются.

## Migration Plan

Одно изменение, обычная сборка и проверка (`./gradlew check -Pheadless=true`, `pitest`). Форматы хранения и внешнее поведение не меняются; откат — revert целиком.
