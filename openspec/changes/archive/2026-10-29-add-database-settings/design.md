## Context

`MainWindowApp.init()` всегда вызывает `Database.open(DataDirectory.databaseFile())`: путь жёстко задан, БД открывается всегда и без проверки схемы. `Database.open(Path)` принимает произвольный путь и создаёт каталоги, но сразу применяет миграции и не умеет ни проверять схему, ни делать бэкап, ни закрываться. Поэтому изменение затрагивает слой БД (create/inspect/migrate с бэкапом/close), настройки и главное окно (меню, состояния, индикатор). `DataDirectory` знает пользовательские каталоги по ОС.

## Goals / Non-Goals

**Goals:** настраиваемый путь БД и автооткрытие; отдельное окно настроек на JavaFX; создание новой БД; безопасная миграция устаревшей БД с подтверждением, бэкапом и откатом; закрытие БД; индикатор состояния.
**Non-Goals:** горячее переключение открытой БД (заменено ручным «Закрыть» + «Открыть»), миграция данных между файлами, downgrade схемы, ротация бэкапов, восстановление после аварийного завершения процесса во время миграции, прочие настройки.

## Decisions

- **Модель**: `record Settings(Path databasePath /* nullable */, boolean autoOpen)`, `Settings.defaults()`; метод `resolvedDatabasePath()` возвращает путь или `DataDirectory.databaseFile()`.
- **Хранение**: `SettingsStore` читает/пишет `java.util.Properties` (`settings.properties`) в каталоге конфигурации (`DataDirectory` получает метод `settingsFile()` рядом с каталогом `bonds2`; тот же базовый каталог по ОС). Ключи `database.path`, `database.autoOpen`. Запись атомарная (временный файл + `Files.move`). Ошибка чтения → defaults. Альтернатива (JSON, `java.util.prefs`) отвергнута: лишняя зависимость / неочевидное расположение.
- **Окно**: `SettingsDialog` — модальный `Stage` (`initModality(APPLICATION_MODAL)`, owner = главное окно): `TextField` + кнопка «Обзор…» (`FileChooser`), `CheckBox`, «Сохранить»/«Отмена». Валидация пути: не каталог, родитель допустим. Логика валидации вынесена в тестируемый не-UI метод.
- **Открытие БД**: перенос из `init()` в `start()` после `stage.show()`; выполнение в `Task` на фоновом потоке, ошибки → `Alert` в FX-потоке. `Database` хранится в `DatabaseController`.
- **API `Database`**: `create(Path[, Duration])` (ошибка, если файл есть; создаёт каталоги, применяет все миграции; при сбое миграции удаляет созданный файл), `inspect(Path)` → вложенный `Database.State {UP_TO_DATE, NEEDS_MIGRATION, TOO_NEW}` через Flyway `info()` и `validateWithResult()` (контрольные суммы проверяются, `migrate()` не вызывается; отсутствующий файл или не-БД → `PersistenceException`), `open(Path[, Duration])` (только при `UP_TO_DATE`, иначе `PersistenceException`; файл не создаёт), `migrateWithBackup(Path)` → `Path` резервной копии (только для `NEEDS_MIGRATION`; иначе `PersistenceException` без копии). Прежний `open(file, timeout)` заменён этим набором. `MigrationException extends PersistenceException` (`PersistenceException` перестал быть `final`).
- **Бэкап**: перед миграцией `PRAGMA wal_checkpoint(TRUNCATE)`, затем копия `bonds2.db` → `<имя>.bak-<yyyyMMdd-HHmmss>` рядом с файлом. При ошибке `migrate()` — удалить `-wal`/`-shm`, вернуть копию поверх файла (`Files.copy REPLACE_EXISTING`) и бросить `MigrationException` с причиной. Успешный бэкап остаётся (ротация вне рамок). Если копию создать не удалось — миграция не стартует. Альтернатива (`VACUUM INTO`) возможна, но простая копия после checkpoint достаточна.
- **Тестируемость**: `create`, `inspect`, `migrateWithBackup` имеют package-private перегрузки с параметром `locations`; публичные методы подставляют `classpath:db/migration`; имя копии в тестах делает предсказуемым package-private `migrateWithBackup(Path, Clock, String...)`. Тестовые наборы миграций лежат в `src/test/resources/migrations/{old,new_ok,new_fail,too_new}`. Миграции, нетранзакционные в SQLite (`VACUUM`, `PRAGMA foreign_keys`, перестройка таблиц), допустимы, поскольку защита обеспечивается резервной копией.
- **Сценарий открытия в UI**: `inspect` → UP_TO_DATE: открыть; NEEDS_MIGRATION: `Alert` CONFIRMATION «Схема БД устарела. Применить миграции? Будет создана резервная копия» → да: `migrateWithBackup` в фоне, затем open; нет: не открывать; TOO_NEW: ошибка. Файла нет: для пути по умолчанию — `create` автоматически, для пользовательского — ошибка «файл не найден» с подсказкой использовать «Создать базу…». Тот же сценарий действует для автооткрытия.
- **«Создать базу…»**: `FileChooser.showSaveDialog`; `create`; при успехе путь записывается в настройки и БД открывается; существующий файл не перезаписывается (ошибка).
- **Жизненный цикл**: `Database implements AutoCloseable`. Внутри `ReentrantReadWriteLock`/счётчик активных транзакций: транзакции берут общую блокировку, `close()` берёт исключительную (ждёт активные), выполняет `PRAGMA wal_checkpoint(TRUNCATE)`, ставит флаг closed и идемпотентен; вызов `close()` изнутри собственной транзакции → `IllegalStateException`; последующие `inTransaction`/`inReadTransaction` бросают `PersistenceException`. `DatabaseController` хранит `Database`, `stop()` приложения вызывает его закрытие.
- **Состояния меню** (`enum DbState` ∈ {CLOSED, OPENING, OPEN, MIGRATING}). `OPENING` — открытие или создание в фоне, включая ожидание согласия на миграцию; введено, чтобы повторный клик не запускал вторую операцию:

  | состояние | Открыть | Создать | Закрыть | Настройки |
  |-----------|---------|---------|---------|-----------|
  | CLOSED    | да      | да      | нет     | да        |
  | OPENING   | нет     | нет     | нет     | нет       |
  | OPEN      | нет     | нет     | да      | да        |
  | MIGRATING | нет     | нет     | нет     | нет       |

  Смена пути в настройках при открытой БД применяется после «Закрыть» + «Открыть»; «Открыть» при открытой БД недоступен, сравнение путей не требуется. Выход и закрытие окна в OPENING и MIGRATING откладываются с сообщением.
- **Структура UI-кода** (пакет `ru.onlychill.bonds2`): `DatabaseController` — вся логика без контролов JavaFX (состояние, сценарии открытия по `inspect` и наличию файла, подтверждение и миграция с бэкапом в фоне, создание, закрытие, проверка выхода, сохранение настроек); `DbState`; `OpenResult` (Opened / NeedsMigration / Failed); `ErrorMessages`; `FxBackground` (фон через `javafx.concurrent.Task`, результат в FX-потоке); `FxDialogs` (Alert-диалоги); `SettingsDialog`; `MainWindowApp` — тонкий слой: меню, строка состояния, автооткрытие после `show()`, `stop()` закрывает БД, только если открыта. Путь по умолчанию передаётся в контроллер параметром (`DataDirectory.databaseFile()`), «путь по умолчанию» означает `databasePath == null`, `Settings.resolvedDatabasePath()` приложением не вызывается.
- **Статусы и сбои**: промежуточные статусы «Открытие базы…», «Создание базы…», «Миграция базы…». Если «Создать базу…» создала БД, но настройки не записались, БД остаётся открытой и показывается предупреждение. Если `close()` не смог перенести WAL, состояние CLOSED и предупреждение. Закрытие БД выполняется синхронно в FX-потоке (фоновых транзакций пока нет; при их появлении `close()` будет ждать).
- **Настройки**: относительный путь отвергается и валидатором, и при загрузке (зависит от рабочего каталога); `SettingsStore.save` при ошибке бросает `UncheckedIOException`.
- **Индикатор состояния**: `Label` в нижней части `BorderPane`, текст берётся из `StringProperty dbStatus`, обновляемого в FX-потоке при каждом исходе (открыта: путь / не открыта + причина / промежуточные статусы).
- Новый путь применяется при следующем открытии/запуске; это показывается в окне подсказкой.

## Risks / Trade-offs

- Аварийное завершение процесса (kill, сбой питания) во время миграции: остаётся `.bak` и БД в частично мигрированном состоянии; следующий запуск увидит `NEEDS_MIGRATION` и сделает новую копию уже из этого состояния. Автоматическое восстановление вне рамок; пользователь может вручную восстановить из первого `.bak`.
- Закрытие окна или «Выход» во время MIGRATING: закрытие блокируется (`setOnCloseRequest` consume, сообщение «Идёт миграция»), пока миграция не завершится; в `stop()` `close()` вызывается, только если БД открыта.
- «Создать базу…» не меняет флаг автооткрытия: он остаётся как был.
- Пользователь меняет путь при открытой БД и ожидает мгновенного эффекта → подсказка в окне; переключение вне рамок.
- Сбой при восстановлении из бэкапа: сообщение содержит путь к копии, чтобы пользователь мог восстановить вручную.
- Недоступный/read-only путь → ошибка в `Alert`, приложение живо.
- Тесты JavaFX-окна хрупки в CI → логика (store, валидация, разрешение пути) тестируется без UI; UI покрывается тем, что уже используется в `MainWindowAppTest`.
