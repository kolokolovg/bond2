# Spec Delta

## MODIFIED Requirements

### Requirement: Пункты меню настроек и открытия БД

Меню «Файл» SHALL содержать пункты «Настройки…» (открывает окно настроек), «Открыть базу» (открывает БД по текущим настройкам), «Создать базу…» (создаёт новую БД в выбранном пользователем месте) и «Закрыть базу». Пункты «Открыть базу» и «Создать базу…» SHALL быть доступны только когда БД не открыта и не идёт миграция; «Закрыть базу» — только когда БД открыта. Отклонение создания из-за изменившегося состояния или начатой остановки SHALL показываться тихо, без диалога ошибки. При выборе файла для новой БД введённое имя без расширения SHALL дополняться расширением `.db`; сообщение о существующем файле SHALL объяснять, что перезапись не выполняется, и предлагать выбрать другое имя.

#### Scenario: Открытие окна настроек
- **WHEN** пользователь выбирает «Файл → Настройки…»
- **THEN** открывается модальное окно настроек

#### Scenario: Ручное открытие БД
- **WHEN** пользователь выбирает «Файл → Открыть базу»
- **THEN** БД открывается по пути из настроек

#### Scenario: Создание новой базы
- **WHEN** пользователь выбирает «Файл → Создать базу…» и указывает файл
- **THEN** по указанному пути создаётся БД с актуальной схемой, путь сохраняется в настройках, БД открывается

#### Scenario: Создание поверх существующего файла
- **WHEN** выбранный файл уже существует
- **THEN** БД не создаётся и существующий файл не изменяется; пользователю показывается сообщение, что перезапись не выполняется и нужно выбрать другое имя

#### Scenario: Дописывание расширения при создании
- **WHEN** пользователь вводит имя файла без расширения в диалоге создания БД
- **THEN** к имени дописывается `.db`, файл создаётся с этим расширением и виден в фильтрах диалогов приложения

#### Scenario: Отклонение создания из-за гонки состояния
- **WHEN** создание БД отклонено из-за изменившегося состояния или начатой остановки, а не из-за ошибки файла
- **THEN** диалог ошибки не показывается, отклонение фиксируется в журнале

## ADDED Requirements

### Requirement: Чтение настроек не блокирует запуск
Чтение файла настроек при запуске SHALL выполняться вне потока интерфейса: поток интерфейса не блокируется дисковым вводом-выводом настроек. Окно собирается и показывается по завершении чтения; предупреждение о сбросе испорченных настроек и решение об автооткрытии принимаются по прочитанным значениям.

#### Scenario: Медленный диск при запуске
- **WHEN** файл настроек читается медленно (сетевой или загруженный диск)
- **THEN** поток интерфейса не блокируется ожиданием чтения, окно показывается по завершении чтения

#### Scenario: Настройки прочитаны до автооткрытия
- **WHEN** запуск завершён
- **THEN** автооткрытие и предупреждение о сбросе настроек определены прочитанными настройками, а не значениями по умолчанию

### Requirement: Закрытие БД при внешнем завершении процесса
При завершении процесса в обход JavaFX (сигнал завершения, остановка из среды разработки) система SHALL выполнить лучшую попытку остановить сервис БД с коротким сроком ожидания. Попытка SHALL быть идемпотентной со штатным выходом: если сервис уже остановлен, она ничего не делает. Гарантий при немедленном уничтожении процесса (SIGKILL) нет — данные восстанавливаются журналом WAL при следующем открытии.

#### Scenario: Внешнее завершение при открытой БД
- **WHEN** процесс получает сигнал завершения, а БД открыта
- **THEN** сервис останавливается в пределах короткого срока, БД закрывается до выхода процесса

#### Scenario: Завершение после штатного выхода
- **WHEN** сервис уже остановлен штатным выходом, затем срабатывает попытка внешнего завершения
- **THEN** попытка ничего не делает и не мешает завершению
