# Design

## Context

См. proposal.md. `FxBackground` запускает недемонов-поток, `DatabaseController.requestExit` в `OPENING` и `MIGRATING` только предупреждает, `Database.inspect` по Flyway `info()` считает любой файл без истории миграций устаревшим.

## Goals / Non-Goals

**Goals:**
- Всегда можно выйти из приложения во время открытия.
- Чужой файл не получает предложение миграции.
- Прерванное создание (пустой файл после обрыва) восстанавливается.

**Non-Goals:**
- Отмена операции Flyway или потока.
- Выход во время миграции.

## Decisions

1. **Выход в `OPENING` спрашивает пользователя через `Dialogs.confirmExitDuringOpen()`** («Дождаться» / «Выйти»). `requestExit` при «Выйти» вызывает `shutdown` с коротким сроком (3 с) и `exit`. Срок задаётся параметром `shutdown(Duration)`; полная версия использует 30 с как прежде. Альтернатива — выходить без вопроса: рискует оборвать создание без предупреждения.
2. **Выход в `MIGRATING` остаётся блокированным** с прежним сообщением: миграция короткая, прерывание процесса посреди миграции оставляет файл в промежуточном состоянии до восстановления.
3. **Поток `bonds2-db` — демон.** Контроллер и без этого ждёт `outcome` в `shutdown`. Недостаток: если процесс завершён во время записи, файл может быть оборван; для создания это даёт пустой файл (см. решение 4), для миграции вход заблокирован (решение 2).
4. **`Database.State` получает `EMPTY` и `FOREIGN`.** `inspect`: размер 0 → `EMPTY`; иначе читаем `sqlite_master` служебным соединением: нет таблиц → `EMPTY`; есть таблицы, но нет `flyway_schema_history` → `FOREIGN`; иначе прежняя логика. Альтернатива — отказ в `migrateWithBackup` для чужих файлов: пользователь уже согласился бы на миграцию.
5. **`attempt` обрабатывает `EMPTY` как инициализацию:** новый метод `Database.initialize(file)` применяет миграции к существующему пустому файлу, при ошибке файл остаётся пустым (не удаляется, так как создан не нами). `FOREIGN` → `Failed("не база bonds2", "Файл … не является базой данных bonds2. Файл не изменён.")`.

## Risks / Trade-offs

- [Диалог выхода — лишний шаг при быстром открытии] → Показывается только пока операция реально идёт.
- [Демон-поток обрывает операцию при выходе] → Выбор «Выйти» осознанный; оборванное создание подбирается как `EMPTY`.
- [Файл SQLite с таблицами и частичной историей Flyway] → Считается своим: есть `flyway_schema_history`, дальше работает прежняя валидация.
