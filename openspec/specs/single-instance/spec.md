# single-instance Specification

## Purpose
Гарантирует, что на один каталог данных работает не более одного экземпляра приложения, чтобы экземпляры не конфликтовали за файлы БД и настроек.

## Requirements

### Requirement: Один экземпляр на каталог данных
Система SHALL разрешать работу только одного экземпляра приложения на каталог данных. Экземпляр SHALL получить эксклюзивную блокировку файла `bonds2.lock` в каталоге данных до чтения настроек и открытия БД и удерживать её до завершения. Блокировка SHALL освобождаться при любом завершении процесса, включая аварийное.

#### Scenario: Первый запуск
- **WHEN** блокировка свободна
- **THEN** экземпляр получает её и продолжает запуск

#### Scenario: Второй запуск
- **WHEN** другой экземпляр уже держит блокировку
- **THEN** новый экземпляр показывает сообщение о том, что приложение уже запущено, не читает настройки, не открывает БД и завершается

#### Scenario: Предыдущий экземпляр завершился аварийно
- **WHEN** файл `bonds2.lock` остался на диске, но процесс-владелец завершён
- **THEN** новый экземпляр получает блокировку и запускается

#### Scenario: Не удалось создать файл блокировки
- **WHEN** каталог данных недоступен для записи
- **THEN** приложение сообщает об ошибке и завершается, не работая без защиты
