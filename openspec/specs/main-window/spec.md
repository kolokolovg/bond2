# main-window Specification

## Purpose
Определяет поведение главного окна приложения: его появление при запуске и штатное завершение работы через меню.

## Requirements

### Requirement: Главное окно при запуске
При запуске приложения система SHALL показать главное окно с заголовком приложения и строкой меню в верхней части.

#### Scenario: Запуск приложения
- **WHEN** пользователь запускает приложение
- **THEN** открывается главное окно с видимой строкой меню

### Requirement: Пункт меню «Выход»
Строка меню SHALL содержать меню «Файл» с пунктом «Выход». Выбор пункта SHALL завершать приложение.

#### Scenario: Выбор «Файл → Выход»
- **WHEN** пользователь открывает меню «Файл» и выбирает «Выход»
- **THEN** главное окно закрывается и процесс приложения завершается с кодом 0

#### Scenario: Закрытие окна штатным способом
- **WHEN** пользователь закрывает главное окно кнопкой закрытия окна
- **THEN** приложение завершается так же, как при выборе «Выход»

### Requirement: Отсутствие консольного режима
Приложение SHALL NOT выводить расчёт купона в консоль и SHALL NOT использовать аргументы командной строки для расчёта; единственный интерфейс — главное окно.

#### Scenario: Запуск с аргументами
- **WHEN** приложение запускается с любыми аргументами командной строки
- **THEN** открывается главное окно, консольный вывод расчёта не выполняется

### Requirement: Пункты меню настроек и открытия БД
Меню «Файл» SHALL содержать пункты «Настройки…» (открывает окно настроек), «Открыть базу» (открывает БД по текущим настройкам), «Создать базу…» (создаёт новую БД в выбранном пользователем месте) и «Закрыть базу». Пункты «Открыть базу» и «Создать базу…» SHALL быть доступны только когда БД не открыта и не идёт миграция; «Закрыть базу» — только когда БД открыта.

#### Scenario: Открытие окна настроек
- **WHEN** пользователь выбирает «Файл → Настройки…»
- **THEN** открывается модальное окно настроек

#### Scenario: Ручное открытие БД
- **WHEN** пользователь выбирает «Файл → Открыть базу»
- **THEN** БД открывается по пути из настроек

#### Scenario: Создание новой базы
- **WHEN** пользователь выбирает «Файл → Создать базу…» и указывает файл
- **THEN** по указанному пути создаётся БД с актуальной схемой, путь сохраняется в настройках, БД открывается

#### Scenario: Создание поверх существующего файла
- **WHEN** выбранный файл уже существует
- **THEN** БД не создаётся и существующий файл не изменяется; пользователю показывается сообщение

### Requirement: Автооткрытие БД после запуска
Если включено автооткрытие, система SHALL открыть БД в фоне после показа главного окна. Если выключено — SHALL NOT открывать БД до явного действия пользователя. Ошибка открытия SHALL показываться пользователю сообщением без аварийного завершения. Если при запуске файл настроек был признан испорченным и сброшен, автооткрытие SHALL NOT создавать БД по пути по умолчанию: при отсутствии файла БД показывается ошибка «файл не найден», существующая БД открывается как обычно.

#### Scenario: Автооткрытие включено
- **WHEN** приложение запускается с включённым автооткрытием
- **THEN** окно показывается, затем БД открывается по пути из настроек

#### Scenario: Автооткрытие выключено
- **WHEN** приложение запускается с выключенным автооткрытием
- **THEN** окно показывается, БД не открывается

#### Scenario: Ошибка открытия
- **WHEN** открыть БД не удалось
- **THEN** показано сообщение об ошибке, главное окно остаётся работоспособным

#### Scenario: После сброса настроек БД по умолчанию нет
- **WHEN** файл настроек был испорчен и сброшен, а файла БД по умолчанию нет
- **THEN** БД не создаётся, показано предупреждение о сбросе и ошибка «файл не найден» с подсказкой про настройки и «Файл → Создать базу…»

#### Scenario: После сброса настроек БД по умолчанию есть
- **WHEN** файл настроек был испорчен и сброшен, а файл БД по умолчанию существует
- **THEN** БД открывается, пользователю показано предупреждение о сбросе

### Requirement: Подтверждение миграции при открытии БД
Если открываемая БД имеет устаревшую схему, система SHALL показать диалог с предложением применить миграции, сообщив, что перед миграцией будет создана резервная копия. До подтверждения БД SHALL NOT изменяться. Пока диалог открыт, закрытие окна и «Файл → Выход» SHALL NOT завершать приложение.

#### Scenario: Пользователь согласился
- **WHEN** открывается БД с устаревшей схемой и пользователь подтверждает миграцию
- **THEN** выполняется миграция с резервной копией, затем БД открывается

#### Scenario: Пользователь отказался
- **WHEN** пользователь отклоняет предложение миграции
- **THEN** БД не открывается и не изменяется

#### Scenario: Неудачная миграция
- **WHEN** миграция завершилась ошибкой
- **THEN** БД восстановлена из резервной копии, пользователю показано сообщение с текстом ошибки миграции

#### Scenario: Закрытие окна во время миграции
- **WHEN** во время выполнения миграции пользователь закрывает окно или выбирает «Файл → Выход»
- **THEN** закрытие не выполняется, показывается сообщение «Идёт миграция»; после завершения миграции окно можно закрыть обычным способом

#### Scenario: Закрытие окна во время диалога миграции
- **WHEN** диалог подтверждения миграции открыт и пользователь пытается закрыть главное окно или выбрать «Файл → Выход»
- **THEN** приложение не завершается, второй диалог не показывается

### Requirement: Индикатор состояния БД
Главное окно SHALL показывать состояние БД в строке состояния: «БД не открыта» (с причиной, если открытие отклонено или завершилось ошибкой) либо «БД открыта: <путь>». Пока выполняется открытие или ожидается решение о миграции, показывается «Открытие базы…».

#### Scenario: БД открыта
- **WHEN** БД успешно открыта
- **THEN** строка состояния показывает «БД открыта» и путь к файлу

#### Scenario: Отказ от миграции
- **WHEN** пользователь отказался от миграции устаревшей БД
- **THEN** строка состояния показывает «БД не открыта» с причиной «схема устарела»

#### Scenario: Автооткрытие выключено
- **WHEN** приложение запущено с выключенным автооткрытием
- **THEN** строка состояния показывает «БД не открыта»

#### Scenario: Ожидание решения о миграции
- **WHEN** открыто окно подтверждения миграции
- **THEN** строка состояния показывает «Открытие базы…»

### Requirement: Закрытие БД
Выбор «Файл → Закрыть базу» SHALL закрывать открытую БД; после этого строка состояния показывает «БД не открыта». При выходе из приложения открытая БД SHALL закрываться так же.

#### Scenario: Закрыть базу
- **WHEN** БД открыта и пользователь выбирает «Файл → Закрыть базу»
- **THEN** БД закрыта, индикатор показывает «БД не открыта», «Открыть базу» и «Создать базу…» становятся доступны

#### Scenario: Выход при открытой БД
- **WHEN** пользователь завершает приложение при открытой БД
- **THEN** БД закрывается до завершения процесса

### Requirement: Запуск второго экземпляра
Если приложение уже запущено, новый экземпляр SHALL NOT показывать главное окно. Он SHALL показать пользователю сообщение о том, что приложение уже запущено, и завершиться.

#### Scenario: Повторный запуск
- **WHEN** пользователь запускает приложение, пока другой экземпляр работает
- **THEN** показывается сообщение «приложение уже запущено», главное окно не открывается, процесс завершается

### Requirement: Завершение приложения во время операции с БД
Если приложение завершается, пока идёт открытие или создание БД, система SHALL дождаться окончания операции не дольше 30 секунд, закрыть получившуюся БД и только затем освободить блокировку единственного экземпляра. По истечении срока ожидание SHALL прекращаться, а процесс SHALL завершаться без ожидания зависшей операции. Если идёт миграция, завершение через меню или закрытие окна SHALL быть отклонено с сообщением «Идёт миграция», а миграция доведена до конца; при завершении в обход меню миграция дожидается окончания (не дольше 30 секунд), а ожидающая решения миграция считается отклонённой.

#### Scenario: Завершение во время открытия
- **WHEN** приложение завершается, пока БД открывается, и операция завершается успешно в пределах срока
- **THEN** открытая БД закрывается до завершения процесса, блокировка экземпляра освобождается после этого

#### Scenario: Завершение во время миграции
- **WHEN** пользователь пытается завершить приложение, пока выполняется миграция
- **THEN** приложение не завершается, показано сообщение «Идёт миграция»; завершение возможно после окончания миграции

#### Scenario: Операция не завершилась в срок
- **WHEN** открытие или создание БД не завершилось за 30 секунд после начала завершения приложения
- **THEN** ожидание прекращается, процесс завершается, не дожидаясь зависшей операции

### Requirement: Поздний результат операции после завершения
Результат фоновой операции открытия, создания или миграции, полученный после начала завершения приложения, SHALL NOT менять состояние БД, строку состояния и SHALL NOT показывать диалоги. Результат закрытия БД SHALL NOT показывать диалоги; состояние «закрыта», опубликованное самой остановкой, применяется. Если результат содержит открытую БД, система SHALL её закрыть.

#### Scenario: Результат пришёл после остановки
- **WHEN** фоновое открытие БД завершилось после начала завершения приложения
- **THEN** полученная БД закрыта, диалоги не показаны

#### Scenario: Ошибка пришла после остановки
- **WHEN** фоновая операция завершилась ошибкой после начала завершения приложения
- **THEN** сообщение об ошибке не показывается
