# code-verification Specification

## Purpose
Определяет автоматические проверки качества и корректности кода: статический анализ, стиль и формальная верификация контрактов.

## Requirements

### Requirement: Статический анализ при компиляции
Компиляция основных исходников (`src/main`) SHALL выполнять статический анализ, включая проверку null-безопасности, и считать найденные ошибки ошибками сборки. Для тестовых исходников Error Prone и NullAway отключены.

#### Scenario: Возможное разыменование null
- **WHEN** код разыменовывает значение, которое может быть null без проверки
- **THEN** компиляция завершается с ошибкой

### Requirement: Анализ дефектов в check
Задача `check` SHALL запускать анализатор дефектов байткода и падать при находках выше допустимого уровня.

#### Scenario: Обнаружен дефект
- **WHEN** анализатор находит дефект выше порога
- **THEN** `./gradlew check` завершается с ошибкой и создаёт отчёт

### Requirement: Контроль форматирования
Сборка SHALL проверять единый стиль кода и предоставлять команду автоматического исправления.

#### Scenario: Нарушение форматирования
- **WHEN** файл не соответствует стилю
- **THEN** `./gradlew check` падает, а `./gradlew spotlessApply` исправляет файл

### Requirement: Формальная верификация контрактов
Проект SHALL предоставлять задачу, статически доказывающую соответствие выделенного модуля его формальным контрактам (пред-/постусловия, инварианты).

#### Scenario: Контракт доказан
- **WHEN** выполняется задача формальной верификации на корректном модуле
- **THEN** все контракты доказаны и задача завершается успешно

#### Scenario: Контракт нарушен
- **WHEN** реализация нарушает постусловие
- **THEN** задача завершается с ошибкой и указывает нарушенный контракт

### Requirement: Единая точка запуска в CI
CI SHALL запускать `check`, мутационное тестирование и формальную верификацию на каждом push и pull request.

#### Scenario: Pull request
- **WHEN** открыт pull request
- **THEN** CI выполняет все проверки и блокирует слияние при провале любой из них

### Requirement: Воспроизводимая загрузка инструмента верификации
Загрузка инструмента формальной верификации SHALL быть самовосстанавливающейся: распаковка идёт во временный каталог сборки, и лишь полный результат атомарно занимает целевое место; готовность задачи определяется наличием инструмента, а не существованием каталога. Повреждённый архив и несовпавшая контрольная сумма отвергаются с внятной ошибкой, не меняя целевого каталога.

#### Scenario: Прерванная загрузка
- **WHEN** предыдущая попытка загрузки прервана и оставила мусор во временном каталоге или целевом месте
- **THEN** повторный запуск выполняет загрузку и распаковку заново и завершается успешно

#### Scenario: Повреждённый архив
- **WHEN** скачанный архив повреждён
- **THEN** задача завершается ошибкой с понятной причиной, целевой каталог не получает частичной распаковки

#### Scenario: Контрольная сумма задана
- **WHEN** свойство контрольной суммы задано и сумма архива не совпадает
- **THEN** загрузка отвергается с сообщением о несовпадении, целевой каталог не меняется

#### Scenario: Готовность определяется инструментом
- **WHEN** целевой каталог существует, но инструмента в нём нет
- **THEN** задача не пропускается как выполненная, а повторяет загрузку
