# app-settings Specification

## Purpose
Определяет пользовательские настройки расположения БД (путь к файлу, автооткрытие при запуске), их сохранение между запусками и окно редактирования настроек.

## Requirements

### Requirement: Настройки расположения БД
Система SHALL поддерживать настройки: путь к файлу БД и флаг автооткрытия БД при запуске. Пустой путь SHALL означать путь по умолчанию (`DataDirectory.databaseFile()`). Значение флага по умолчанию — «включено».

#### Scenario: Первый запуск без файла настроек
- **WHEN** файла настроек нет
- **THEN** используются путь по умолчанию и автооткрытие включено

#### Scenario: Заданный путь
- **WHEN** в настройках указан путь к файлу БД
- **THEN** именно этот файл используется при открытии БД

### Requirement: Хранение настроек

Система SHALL сохранять настройки в платформенном хранилище пользователя (`java.util.prefs`: реестр на Windows, XML-файл в домашнем каталоге на macOS и Linux) и восстанавливать их при следующем запуске. Отсутствующее значение SHALL давать значение по умолчанию без прерывания запуска; некорректное значение SHALL заменяться значением по умолчанию с записью события в журнал.

#### Scenario: Перезапуск
- **WHEN** пользователь сохранил настройки и перезапустил приложение
- **THEN** сохранённые значения применены

#### Scenario: Отсутствующее значение
- **WHEN** в хранилище нет значения для ключа (первый запуск или значение не записывалось)
- **THEN** применяется значение по умолчанию, запуск не прерывается, предупреждение не показывается

#### Scenario: Некорректное значение
- **WHEN** значение в хранилище не разбирается как допустимый путь к БД или флаг
- **THEN** применяется значение по умолчанию для этого ключа, событие записывается в журнал

### Requirement: Редактирование настроек

Система SHALL предоставить отдельное модальное окно настроек с полем пути к файлу БД, кнопкой выбора файла, флажком «Открывать базу при запуске» и кнопками «Сохранить» и «Отмена». Сохранение SHALL выполняться синхронно: после нажатия «Сохранить» значения проверяются, записываются в хранилище и окно закрывается; при ошибке записи окно SHALL показать причину и остаться открытым, а после перезапуска применяются прежние значения.

#### Scenario: Сохранение
- **WHEN** пользователь изменил значения и нажал «Сохранить»
- **THEN** настройки записаны в хранилище, окно закрыто

#### Scenario: Отмена
- **WHEN** пользователь нажал «Отмена» или закрыл окно
- **THEN** настройки не изменены

#### Scenario: Недопустимый путь
- **WHEN** путь не является допустимым путём к файлу (например, указывает на существующий каталог)
- **THEN** окно показывает ошибку, настройки не сохраняются

#### Scenario: Сохранение не блокирует интерфейс
- **WHEN** пользователь нажимает «Сохранить»
- **THEN** запись выполняется синхронно в потоке интерфейса и не воспринимается как задержка: платформенное хранилище пишется за миллисекунды

#### Scenario: Ошибка записи
- **WHEN** запись в хранилище завершилась ошибкой
- **THEN** окно остаётся открытым и показывает причину; после перезапуска применяются прежние значения
