# app-settings Specification

## Purpose
Определяет пользовательские настройки расположения БД (путь к файлу, автооткрытие при запуске), их сохранение между запусками и окно редактирования настроек.

## Requirements

### Requirement: Настройки расположения БД
Система SHALL поддерживать настройки: путь к файлу БД и флаг автооткрытия БД при запуске. Пустой путь SHALL означать путь по умолчанию (`DataDirectory.databaseFile()`). Значение флага по умолчанию — «включено».

#### Scenario: Первый запуск без файла настроек
- **WHEN** файла настроек нет
- **THEN** используются путь по умолчанию и автооткрытие включено

#### Scenario: Заданный путь
- **WHEN** в настройках указан путь к файлу БД
- **THEN** именно этот файл используется при открытии БД

### Requirement: Сохранение настроек

Система SHALL сохранять настройки в файле конфигурации в пользовательском каталоге и восстанавливать их при следующем запуске. Повреждённый или нечитаемый файл настроек SHALL NOT мешать запуску: применяются значения по умолчанию (см. «Восстановление испорченного файла настроек»). Файл, начинающийся с метки порядка байтов UTF-8, SHALL читаться корректно: метка не делает ключи нечитаемыми и не считается повреждением.

#### Scenario: Перезапуск
- **WHEN** пользователь сохранил настройки и перезапустил приложение
- **THEN** сохранённые значения применены

#### Scenario: Повреждённый файл настроек
- **WHEN** файл настроек не удаётся разобрать
- **THEN** приложение запускается со значениями по умолчанию

#### Scenario: Файл с меткой порядка байтов
- **WHEN** файл настроек начинается с метки порядка байтов UTF-8, а затем содержит корректные ключи
- **THEN** ключи распознаются, применяются значения из файла, сброс к значениям по умолчанию не выполняется и предупреждение не показывается

### Requirement: Восстановление испорченного файла настроек
Система SHALL копировать испорченный файл настроек в `settings.properties.bad-<yyyyMMdd-HHmmss>` рядом с ним (при совпадении имени добавляется числовой суффикс), записывать на его место значения по умолчанию и применять их. Для файла нулевой длины копия SHALL NOT создаваться: содержимого, которое стоило бы сохранить, в нём нет. Сбой копирования или записи не мешает запуску и пишется в лог.

#### Scenario: Файл настроек не читается
- **WHEN** файл настроек не удаётся разобрать
- **THEN** его копия сохранена как `settings.properties.bad-<метка времени>`, файл настроек содержит значения по умолчанию, приложение запускается с ними, пользователю показано предупреждение с путём к копии

#### Scenario: Копию создать не удалось
- **WHEN** копирование или запись значений по умолчанию завершились ошибкой
- **THEN** приложение запускается со значениями по умолчанию, ошибка записана в лог, пользователю показано предупреждение без пути к копии

#### Scenario: Файл нулевой длины
- **WHEN** файл настроек существует и имеет нулевую длину
- **THEN** копия не создаётся, файл настроек содержит значения по умолчанию, пользователю показано предупреждение о сбросе без пути к копии

### Requirement: Признаки испорченного файла настроек
Испорченным SHALL считаться файл настроек, который не читается, имеет нулевую длину или содержит значения, не разбираемые как путь к БД (только абсолютный) и флаг `true`/`false`. Отсутствие файла, ключей и пустой путь повреждением SHALL NOT считаться.

#### Scenario: Относительный путь к БД
- **WHEN** в файле настроек путь к БД относительный
- **THEN** файл копируется и сбрасывается, как повреждённый, пользователю показано предупреждение

#### Scenario: Неверное значение флага
- **WHEN** флаг автооткрытия равен значению, отличному от `true` и `false`
- **THEN** файл копируется и сбрасывается, как повреждённый, пользователю показано предупреждение

#### Scenario: Файл нулевой длины
- **WHEN** файл настроек существует, но пуст
- **THEN** он считается повреждённым, настройки сбрасываются к значениям по умолчанию, пользователю показано предупреждение

#### Scenario: Первый запуск не считается повреждением
- **WHEN** файла настроек нет или в нём нет части ключей
- **THEN** копия не создаётся, предупреждение не показывается, отсутствующие значения берутся по умолчанию

### Requirement: Предупреждение о сбросе настроек
После сброса испорченного файла настроек система SHALL показать пользователю предупреждение, что настройки были повреждены и сброшены, с путём к копии (если она создана).

#### Scenario: Предупреждение после сброса
- **WHEN** испорченный файл настроек был сброшен при запуске
- **THEN** пользователю показано предупреждение о сбросе; путь к копии указан, если копия создана

### Requirement: Окно настроек

Система SHALL предоставить отдельное модальное окно настроек с полем пути к файлу БД, кнопкой выбора файла, флажком «Открывать базу при запуске» и кнопками «Сохранить» и «Отмена». Запись настроек при сохранении SHALL выполняться вне потока интерфейса: окно остаётся отзывчивым на время дискового ввода-вывода. На время записи элементы управления окна и его закрытие SHALL быть заблокированы: окно закрывается только после успешной записи, а при ошибке показывает причину и разблокируется.

#### Scenario: Сохранение
- **WHEN** пользователь изменил значения и нажал «Сохранить»
- **THEN** настройки записаны в файл, окно закрыто

#### Scenario: Отмена
- **WHEN** пользователь нажал «Отмена» или закрыл окно, и записи в этот момент нет
- **THEN** настройки не изменены

#### Scenario: Недопустимый путь
- **WHEN** путь не является допустимым путём к файлу (например, указывает на существующий каталог)
- **THEN** окно показывает ошибку, настройки не сохраняются

#### Scenario: Сохранение не блокирует интерфейс
- **WHEN** пользователь нажимает «Сохранить», а запись файла настроек на диск идёт медленно
- **THEN** поток интерфейса не блокируется записью, окно закрывается после её завершения

#### Scenario: Отмена во время записи
- **WHEN** запись запущена и пользователь нажимает «Отмена» или закрывает окно крестиком
- **THEN** окно не закрывается и настройки не сбрасываются: кнопки «Сохранить», «Отмена» и «Обзор…» недоступны до завершения записи, затем окно закрывается при успехе или показывает ошибку записи

#### Scenario: Повторное сохранение во время записи
- **WHEN** запись запущена и пользователь снова нажимает «Сохранить» (или Enter)
- **THEN** вторая запись не запускается, первая завершается как обычно

#### Scenario: Ошибка записи
- **WHEN** запись завершилась ошибкой
- **THEN** окно остаётся открытым и показывает причину ошибки, элементы управления разблокированы, прежние настройки действуют
### Requirement: Надёжная запись настроек
Система SHALL сбрасывать содержимое временного файла настроек на диск до его атомарной замены, чтобы после потери питания файл настроек содержал либо прежние, либо новые значения целиком. Временные файлы записи настроек, оставшиеся после сбоя, SHALL удаляться при следующем чтении настроек.

#### Scenario: Запись настроек
- **WHEN** настройки сохраняются
- **THEN** данные сброшены на диск до замены файла, прежний файл заменяется атомарно

#### Scenario: Оставшийся временный файл
- **WHEN** при чтении настроек рядом с файлом найден временный файл записи от прерванного сохранения
- **THEN** он удалён, настройки прочитаны из основного файла

### Requirement: Запись настроек при завершении приложения

Незавершённая запись настроек при завершении приложения SHALL ожидаться до смерти
процесса не дольше заданного срока (5 секунд), в любом пути завершения, включая хук
внешнего завершения. По истечении срока завершение SHALL продолжаться, событие SHALL
фиксироваться в журнале; целость файла обеспечивает атомарная замена.

#### Scenario: Выход во время записи настроек

- **WHEN** запись настроек запущена и приложение завершается через меню или окно
- **THEN** запись доводится до конца до смерти процесса, если укладывается в срок

#### Scenario: Внешнее завершение во время записи настроек

- **WHEN** процесс получает сигнал завершения, пока идёт запись настроек
- **THEN** запись ожидается в пределах срока, процесс завершается после её окончания или по истечении срока

#### Scenario: Запись не уложилась в срок

- **WHEN** запись настроек не завершилась за 5 секунд ожидания
- **THEN** процесс завершается, файл настроек содержит прежние или новые значения целиком, событие зафиксировано в журнале
