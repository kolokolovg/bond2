# bonds2

Приложение на Java 21 (Gradle) с встроенными тестами и инструментами верификации кода.

## Требования

Нужен любой JDK для запуска Gradle (17+; `JAVA_HOME` или `java` в `PATH`). JDK 21 для компиляции Gradle скачает сам через toolchain (foojay), если его нет локально.

## Сборка и запуск

```bash
./gradlew build                      # сборка + все обязательные проверки
./gradlew run                        # запуск: открывается главное окно (JavaFX)
```

Главное окно содержит меню «Файл»: «Настройки…», «Открыть базу», «Создать базу…», «Закрыть базу» и «Выход», завершающее приложение. Консольного режима нет. Тесты UI по умолчанию идут на реальном дисплее; без дисплея запускайте их с `-Pheadless=true` (см. «Тесты»).

## Хранилище данных (SQLite)

Данные хранятся в локальной БД SQLite (JDBC `sqlite-jdbc`), схема версионируется миграциями Flyway из `src/main/resources/db/migration/`. Миграции применяются при создании БД, при инициализации пустого файла или после подтверждения при открытии БД с устаревшей схемой (см. раздел «Настройки и база данных»). Файл по умолчанию: Linux — `$XDG_DATA_HOME/bonds2/bonds2.db` (по умолчанию `~/.local/share/bonds2/`), macOS — `~/Library/Application Support/bonds2/`, Windows — `%LOCALAPPDATA%\bonds2\`. Переменные `XDG_DATA_HOME` и `LOCALAPPDATA` учитываются, только если заданы абсолютным путём. Путь можно изменить в настройках.

Атомарность и параллельная работа: `Database.inTransaction` (запись, `BEGIN IMMEDIATE`, commit/rollback) и `Database.inReadTransaction` (чтение). БД работает в режиме WAL с `busy_timeout` (5 с), поэтому читатели не блокируют писателя, а конкурирующие записи ждут освобождения блокировки. Транзакции и закрытие БД открывают существующий файл без права его создать: если файл БД удалён или перемещён во время работы, транзакция или закрытие завершается ошибкой, а пустой файл по этому пути не появляется. Вызовы синхронные — из потока JavaFX их лучше выносить в фон.

Файл БД должен лежать на локальном диске: WAL ненадёжен на сетевых файловых системах (NFS, SMB/CIFS и подобных). Транзакции работают с `synchronous=FULL`: зафиксированная транзакция переживает потерю питания и сбой операционной системы. Приложение однопользовательское и однопроцессное: один файл БД обслуживает один экземпляр приложения (блокировка `bonds2.lock` лежит в каталоге данных). Защиты от нескольких профилей, указывающих на один файл БД, нет.

## Настройки и база данных

### Файл настроек

Настройки хранятся в файле `settings.properties` в каталоге данных приложения, рядом с файлом БД по умолчанию:

- Linux — `$XDG_DATA_HOME/bonds2/settings.properties` (по умолчанию `~/.local/share/bonds2/settings.properties`);
- macOS — `~/Library/Application Support/bonds2/settings.properties`;
- Windows — `%LOCALAPPDATA%\bonds2\settings.properties`.

| Ключ | Значение | По умолчанию |
| --- | --- | --- |
| `database.path` | абсолютный путь к файлу БД; пустое значение — путь по умолчанию (`bonds2.db` в каталоге данных) | пусто |
| `database.autoOpen` | `true` или `false`: открывать БД при запуске | `true` |

Файл можно править вручную. Отсутствующий, нечитаемый или повреждённый файл не мешает запуску: применяются значения по умолчанию; повреждённый файл копируется в `settings.properties.bad-<метка времени>`. Файл нулевой длины тоже считается повреждённым, но копия для него не создаётся: в нём нет данных, которые стоило бы сохранить. Приложение предупреждает о сбросе и не создаёт БД по умолчанию автоматически (если файла БД нет, создайте её через «Файл → Создать базу…»). Окно настроек записывает файл атомарно: новые значения сначала сбрасываются на диск во временный файл, а затем заменяют прежний. Временные файлы `settings-*.tmp`, оставшиеся после сбоя записи, удаляются при следующем запуске.

### Окно настроек

«Файл → Настройки…» открывает модальное окно: поле пути (можно ввести вручную или выбрать файл через «Обзор…»), флажок «Открывать базу при запуске», кнопки «Сохранить» и «Отмена». Путь проверяется до сохранения: он должен быть полным, не указывать на каталог, а каталог файла должен существовать или создаваться.

### Открытие, создание и закрытие

- Если включено автооткрытие, БД открывается после показа окна. Ошибка открытия показывается сообщением, приложение продолжает работать.
- «Файл → Открыть базу» открывает БД по пути из настроек. Если в настройках путь не задан и файла по умолчанию нет, он создаётся автоматически; если путь задан явно (даже совпадающий с умолчанием), а файла нет, приложение сообщит об этом. Если файла нет по явно заданному пути, приложение сообщит об этом: создайте базу через «Создать базу…».
- «Файл → Создать базу…» создаёт новую БД с актуальной схемой в выбранном файле, записывает путь в настройки и открывает БД. Существующий файл не перезаписывается. Флаг автооткрытия при этом не меняется.
- «Файл → Закрыть базу» переносит журнал WAL в файл и закрывает БД. Если файл БД к этому моменту удалён или перемещён, закрытие сообщит об ошибке и не создаст пустой файл на его месте. При выходе из приложения открытая БД закрывается так же.
- Пустой файл (0 байт) по пути БД и SQLite-файл без объектов схемы (`sqlite_master` пуст, `application_id` и `user_version` равны 0) инициализируются актуальной схемой без вопроса о миграции. Если инициализация не удалась, файл возвращается к пустому состоянию и не удаляется, поэтому повторная попытка возможна.
- Чужая SQLite-база, то есть файл без истории миграций приложения, в котором есть таблицы, views, triggers, индексы, служебные таблицы `sqlite_*` либо ненулевые `application_id`/`user_version`, не открывается и не меняется: строка состояния показывает «БД не открыта: не база bonds2», миграция не предлагается.
- Строка состояния внизу окна показывает «БД открыта: <путь>» или «БД не открыта» с причиной, например «схема устарела».

### Миграции и резервные копии

Если схема БД устарела, перед открытием приложение спрашивает разрешение на миграцию. Без согласия файл не меняется и БД не открывается. С согласием перед миграцией создаётся резервная копия `<имя файла>.bak-<ГГГГММДД-ЧЧММСС>` рядом с БД, например `bonds2.db.bak-20261029-101530`. Копия снимается командой SQLite `VACUUM INTO`: она включает данные из журнала WAL, а её целостность проверяется. Если копию создать не удалось, миграция не выполняется, файл БД не меняется. При совпадении метки времени к имени добавляется числовой суффикс (`-1`, `-2`…). После любой попытки миграции, успешной или неудачной, хранятся три копии этого файла БД: новая и две самые новые из остальных, более старые удаляются. Новая копия не удаляется ни при каком порядке меток времени, например после перевода часов назад, когда старые копии могут оказаться с более поздними метками.

Если миграция завершилась ошибкой, файл БД восстанавливается из резервной копии: копия сначала переносится во временный файл рядом с БД, а затем атомарно заменяет её. При сбое временный файл удаляется, а сообщение содержит путь к копии для ручного восстановления. Схема, новее версии приложения, не открывается.

Пока идёт открытие, создание или миграция, пункты меню (кроме «Выход») заблокированы. Выход и закрытие окна во время миграции отклоняются с сообщением «Идёт миграция»: миграция короткая и защищена резервной копией. Если выход запрошен, пока открыт диалог подтверждения миграции, диалог закрывается, миграция считается отклонённой (файл БД не меняется), приложение завершается. Если выход запрошен до показа диалога (пока БД открывается, а открытие возвращает «нужна миграция»), диалог не показывается, миграция не запускается и считается отклонённой, файл БД не меняется, сообщение «Идёт миграция» не показывается, приложение завершается. Остановка сервиса идёт в фоне и не блокирует окно; повторный запрос выхода игнорируется. Диалоги не блокируют поток интерфейса, но остаются модальными. Во время открытия или создания БД вопроса «Выйти» нет: приложение ждёт окончания операции не дольше 30 секунд, закрывает получившуюся БД и только затем освобождает блокировку единственного экземпляра; по истечении срока ожидание прекращается и процесс завершается без ожидания зависшей операции (поток `bonds2-db` — демон). При завершении в обход меню открытие или создание ждёт не дольше 5 секунд, идущая миграция дожидается окончания (до 30 секунд), а ожидающая решения считается отклонённой.

### Единственный экземпляр

Приложение удерживает блокировку `bonds2.lock` в каталоге данных. Второй экземпляр не открывает окно и БД: он показывает сообщение «приложение уже запущено» и завершается.

Жизненным циклом БД (открытие, создание, миграция, закрытие, остановка) владеет `DatabaseService` из пакета `ru.onlychill.bonds2.dbservice`: он не зависит от JavaFX, выполняет операции строго по одной на потоке `bonds2-db` и публикует состояние через `java.util.concurrent.Flow.Publisher`. `DatabaseController` из пакета `ru.onlychill.bonds2.ui` — тонкий адаптер: он подписывается на состояние, переносит его в поток JavaFX и показывает диалоги. «Файл → Закрыть базу» не блокирует окно.

### Смена файла БД

Новый путь из настроек применяется при следующем открытии. Чтобы перейти на другой файл, закройте текущую БД («Файл → Закрыть базу»), затем откройте её снова («Файл → Открыть базу»).

## Тесты

| Команда | Что делает |
| --- | --- |
| `./gradlew test` | модульные (JUnit + AssertJ) и property-based (jqwik) тесты, затем отчёт JaCoCo |
| `./gradlew jacocoTestCoverageVerification` | падает, если покрытие строк ниже `coverage.minLine` (0.80) |
| `./gradlew pitest` | мутационное тестирование (PIT), порог `mutation.threshold` (70%); отчёт `build/reports/pitest/` |

Без графического дисплея (CI, SSH) добавьте `-Pheadless=true`: JavaFX работает в headless-режиме Monocle для `test` и `pitest`. Monocle входит в JDK с JavaFX (например, Liberica Full), на обычном Temurin флаг не сработает.

Пороги задаются в `gradle.properties` и переопределяются, например: `-Pcoverage.minLine=0.9`.
Отчёт покрытия: `build/reports/jacoco/test/html/index.html`. `check` включает тесты и проверку покрытия, но не `pitest` (он медленнее; запускается в CI отдельно).

## Статический анализ и стиль

Всё ниже входит в `./gradlew check`:

- **Error Prone + NullAway** — при компиляции; нарушение null-безопасности (`@Nullable` из JSpecify) — ошибка сборки. Проверяются только основные исходники (`src/main`, пакеты `ru.onlychill.bonds2`); для тестов Error Prone отключён.
- **SpotBugs** — анализ байткода (`spotbugsMain`, `spotbugsTest`), отчёты в `build/reports/spotbugs/`.
- **Spotless** (google-java-format, ktlint для `*.gradle.kts`) — `./gradlew spotlessCheck` проверяет, `./gradlew spotlessApply` исправляет.

## Формальная верификация (JML + OpenJML)

Чистая арифметика купона вынесена в `src/verified/java/ru/onlychill/bonds2/bond/CouponMath.java` и снабжена JML-контрактами (пред-/постусловия). Каталог входит в основной source set, поэтому код одновременно компилируется и доказывается.

```bash
./gradlew openjmlProve   # статическое доказательство контрактов (OpenJML ESC)
```

- Первый запуск скачивает OpenJML (`openjml.version` в `gradle.properties`, ~500 МБ) в `tools/` (в `.gitignore`).
- OpenJML поставляется со своим JDK 21, поэтому весь проект использует Java 21: единая версия для компиляции, тестов, анализаторов и верификации. Переход на более новую Java возможен только после выхода OpenJML с её поддержкой.
- Спецификации пишутся блочными комментариями `/*@ ... @*/`: google-java-format портит строчные `//@`.
- Нарушенный контракт приводит к ненулевому коду выхода и сообщению `The prover cannot establish an assertion (Postcondition ...)`.
- Задача не входит в `check` (долгая загрузка и работа), но обязательна в CI.

## CI

`.github/workflows/ci.yml` на каждый push и pull request выполняет `./gradlew check pitest openjmlProve -Pheadless=true` на JDK Liberica Full (с JavaFX).
